# Phase 238.3 — Persist Claude Code as default agent

## Context

Phase 238.2 (built-in skill rebrand) shipped. Operator continued "devam et". Probe of `/api/agents` revealed:
- 3 agents available: Aion CLI (id=632f31d2, agent_type=aionrs), Claude Code (id=2d23ff1c, agent_type=acp), OpenCode (id=53861a53)
- `client_settings.guid.lastSelectedAgent = "aionrs"` — Aion CLI was the active default
- Phase 236 had previously set this to `"2d23ff1c"` (Claude Code) but the value reverted to `"aionrs"` at some point (cause unknown — possibly a reseed path in AionUi backend, or an out-of-band mutation)

Operator clarified: "Disable etmene gerek yok cli kalabilir" = no need to disable, the CLI can stay in the picker. Only the DEFAULT needs to point at Claude Code.

## Discovery

PUT `guid.lastSelectedAgent` works and persists across `systemctl restart liv-assistant`:
```
PUT /api/settings/client {"guid.lastSelectedAgent":"2d23ff1c"} → success
GET /api/settings/client → lastSelectedAgent = 2d23ff1c
systemctl restart liv-assistant
GET /api/settings/client → lastSelectedAgent = 2d23ff1c  (PERSISTS)
```

Mini PC is currently in the desired state (verified above). What remains is to make this state survive a future hypothetical reseed — which an idempotent post-restart helper guarantees.

## Fix scope

**IN scope (Phase 238.3)**:
- New helper: `scripts/set-default-liv-agent.sh` — idempotent post-restart helper. Reads current `guid.lastSelectedAgent`; if not `"2d23ff1c"`, PUTs it + normalizes `agents.hidden:[]` + `agents.disabled:[]`. Never fails the deploy on transient API issues.
- `update.sh` integration: invoke the helper RIGHT AFTER `capture-liv-assistant-password.sh` post-restart (so AionUi is guaranteed to be listening on :3020). Mirrors the existing TEMP_DIR/LIVOS_DIR fallback pattern.

**OUT of scope (per operator preference)**:
- Disabling or hiding Aion CLI — operator explicitly said it can stay visible
- Caddy server-side response rewrite of `/api/agents` body — Caddy v2.11.3 on Mini PC has no `http.handlers.replace_response` plugin (only `caddy.logging.encoders.filter.replace` for log encoding)
- Sed-replacing the Bun ELF binary — Phase 234-03 design rule prohibits
