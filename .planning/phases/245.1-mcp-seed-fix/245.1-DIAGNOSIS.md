## Root Cause

### Gap 1: luse env-thread incomplete

The seed payload at `scripts/install/seeds/mcp-servers.json` only declares 3 of
the 7 vars the luse MCP server resolves at startup. Missing:

| Var                  | Source                                     |
|----------------------|--------------------------------------------|
| `LIVINITYD_API_URL`  | static `http://127.0.0.1:8080`             |
| `LIV_API_KEY`        | `/opt/livos/.env` → `LIV_API_KEY=...`      |
| `LUSE_USER_SLUG`     | single-user v43 → `bruce`                  |
| `LUSE_DOMAIN_ROOT`   | static `livinity.io`                       |

Without these, `[luse-mcp] resolver: env-thread incomplete` warning fires on
every spawn; `redis` stays `null`; `create_stream` is gated off.

### Gap 2: 4 of 5 system MCPs default-disabled

`luse` is the only system MCP with `enabled: true` in `mcp-servers.json`.
`liv-docker`, `liv-system`, `liv-apps`, `liv-vault` all carry `enabled: false`.

In Phase 241's seed orchestrator (`seed.ts` Stage 4b), the toggleServer call is
gated by `target.cfg.enabled === true`. So 4 of 5 system MCPs are auto-created
in AionUi disabled.

Operator declared the 5 system MCPs **mandatory** — all should ship enabled.

### Gap 3 (downstream): `liv-apps` / `liv-docker` / `liv-system` / `liv-vault` env

`liv-apps.description` literally states `Needs LIVINITYD_API_URL + LIV_API_KEY
env wired via the UI before enabling.` But the seed never wires it. The 4
local MCPs all need at minimum `LIVINITYD_API_URL` + `LIV_API_KEY` to talk back
to livinityd's HTTP API.

## Planned Fix (3 atomic commits)

### Task 1 (this file)
Audit + diagnosis.

### Task 2 — Patch seed payload + install loader + tests

**File: `scripts/install/seeds/mcp-servers.json`**

- `luse.env`: add 4 vars
  - `LIVINITYD_API_URL: "http://127.0.0.1:8080"` (static)
  - `LIV_API_KEY: "__LIVOS_LIV_API_KEY__"` (placeholder, substituted at install-time)
  - `LUSE_USER_SLUG: "__LIVOS_USER_SLUG__"` (default `bruce` single-user v43)
  - `LUSE_DOMAIN_ROOT: "__LIVOS_DOMAIN_ROOT__"` (default `livinity.io`)
- `liv-apps` / `liv-docker` / `liv-system` / `liv-vault`:
  - Add `env: { LIVINITYD_API_URL, LIV_API_KEY }` (placeholders)
  - Flip `enabled: false → true`

**File: `scripts/install/deploy-livinityd.sh`**

`_dld_seed_mcp_servers` substitution extended from 1 placeholder to 4:

```bash
substituted_json=$(sed \
  -e "s|__LIVOS_REDIS_URL__|${redis_url}|g" \
  -e "s|__LIVOS_LIV_API_KEY__|${liv_api_key}|g" \
  -e "s|__LIVOS_USER_SLUG__|${user_slug}|g" \
  -e "s|__LIVOS_DOMAIN_ROOT__|${domain_root}|g" \
  "$seed_file")
```

`liv_api_key` read from `_DLD_ENV_FILE` (grep `^LIV_API_KEY=`); `user_slug`
defaults to `bruce`; `domain_root` defaults to `livinity.io`.

If `liv_api_key` is empty (no `LIV_API_KEY=` line in .env), warn + leave
placeholder unsubstituted — the runtime resolver already emits the
`env-thread incomplete` warning in that case, which is the documented
behavior for missing API key.

**File: `livos/packages/livinityd/source/modules/mcp-registrar/__tests__/seed.test.ts`**

## Pitfall 1 Preservation

Phase 241 D-241-04 strict GET-and-skip means that **after** the 245.1
re-seed lands, any operator manual edit to (e.g.) `luse.env.XAUTHORITY` will
again be preserved across livinityd restarts. The DELETE+re-seed in Task 3
is a **one-time** catalog upgrade for the v43-shipped boxes that received
the old payload. Going forward, the EXISTS gate continues to honor operator
customizations.

## Non-Destructive Guarantee

The seed payload patch only adds keys; no existing operator UI edit is
clobbered because:

- Pitfall 1 (re-POST on existing name): orchestrator never POSTs over an
  existing server name. The Task 3 DELETE step is a deliberate one-shot
  ratchet, NOT a recurring overwrite.
- `filesystem` (operator-added MCP) lives in the same Redis hash but is
  NOT in `SYSTEM_MCP_NAMES_SET` — `readSystemMcpCatalog` filters it out and
  it is never touched by the seed orchestrator.
