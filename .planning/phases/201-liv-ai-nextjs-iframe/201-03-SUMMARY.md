# Phase 201 Plan 03: Port tool-renderers + 11 tool-ui primitives + redact + native approve fetch — Summary

Ported the Phase 198-03/04 generative UI surface 1:1 into the Next.js subapp. 14 tool-ui primitives + 16 ToolUI registrations (10 generative + 6 HITL ApprovalCard) now live under `livos/packages/liv-ai-app/src/lib/{tool-ui,liv-ai}/`, mounted inside `<Thread>` so every tool call paints rich UI. The HITL approve mutation uses native fetch against parent livinityd `/trpc/mastra.agent.approve?batch=1` with `credentials: 'include'` (D-201-18 — subapp does not import Mastra or tRPC client), while preserving the original `{approve, reject, isPending}` public API so the verbatim tool-renderers port keeps importing the hook unchanged.

- **shadcn primitive added**: `table` (consumed by `data-table.tsx`). All other shadcn primitives mentioned in the plan's candidate list (`button avatar collapsible badge tooltip dropdown-menu`) turned out to be either already present from the 201-01 scaffold (`button`, `avatar`, `collapsible`, `tooltip`) or unused by the verbatim ports (`badge`, `dropdown-menu` — neither appears in the 14 primitives).

## Deviations from Plan

### Rule-1 (bug-fix) — Plan Task 2's `use-approve-mutation` example would break compilation

- **Found during:** Task 2 (before writing the file).
- **Issue:** The plan example exports `{ mutate, isPending }`, but `tool-renderers.tsx` (D-201-20 FROZEN — verbatim port) consumes `{ approve, reject, isPending }` at lines 403/410-412 inside `makeApprovalToolUI`. Implementing the plan example literally would have caused TypeScript errors and a non-functional Approve/Reject flow.
- **Fix:** Kept the original P198-04 `UseApproveMutationResult` interface `{ approve, reject, isPending }` and only swapped the transport (tRPC React useMutation → native fetch). Both `approve(toolCallId)` and `reject(toolCallId)` call a shared `fire({toolCallId, approved})` helper that POSTs to `/trpc/mastra.agent.approve?batch=1` with the tRPC v10 batch body shape `{ "0": { json: input } }`, `credentials: 'include'` so the parent JWT cookie auto-flows (D-201-06 same-origin iframe pattern).
- **Files modified:** `livos/packages/liv-ai-app/src/lib/liv-ai/use-approve-mutation.ts` (NEW).
- **Acceptance criteria still satisfied:** 1 hit for the URL substring, 0 hits for tRPC client identifiers.

### Rule-3 (blocking) — React 19 removed the global JSX namespace, breaking `approval-card.tsx` TS check

- **Found during:** Task 3 first `pnpm build` attempt.
- **Issue:** `approval-card.tsx` line 49 originally declared the return type as `: JSX.Element`. Under React 19's updated `@types/react`, `JSX` is no longer a global namespace, so `next build` failed type-check with `Cannot find namespace 'JSX'`.
- **Fix:** Dropped the explicit `: JSX.Element` annotation. TypeScript infers the function's JSX return type identically — zero behavior change, smallest possible delta.
- **Files modified:** `livos/packages/liv-ai-app/src/lib/tool-ui/approval-card.tsx` (1-line change to the function signature).

### Rule-3 (blocking) — `react-leaflet` accesses `window` at module-evaluation time, breaking Next.js static prerender

- **Found during:** Task 3 second `pnpm build` attempt (after the JSX fix).
- **Issue:** `geo-map.tsx` imports `react-leaflet` + `leaflet` + `leaflet/dist/leaflet.css` at top level. Even though the `Assistant` shell is `'use client'`, Next.js still loads the client modules during the static prerender pass for `app/page.tsx`, and `react-leaflet`'s module evaluation references `window` — the build crashed with `ReferenceError: window is not defined` during the `Export encountered an error on /page: /` step.
- **Fix:** Split `geo-map.tsx` into two files (Rule-3 Next.js environment adapter — zero behavior change to the render output):
  1. `geo-map.tsx` — tiny client-only wrapper that re-exports `GeoMap` via `next/dynamic(() => import('./geo-map-impl').then(m => m.GeoMapImpl), { ssr: false, loading: <muted "Loading map…" chip> })`.
  2. `geo-map-impl.tsx` — verbatim copy of the original `GeoMap` body (DivIcon + MapContainer + TileLayer + Marker + Popup), wrapped in `'use client'`. Only ever loaded in the browser.
- **Files modified/created:** `livos/packages/liv-ai-app/src/lib/tool-ui/geo-map.tsx` (rewrite — wrapper only) + `livos/packages/liv-ai-app/src/lib/tool-ui/geo-map-impl.tsx` (NEW — verbatim impl).

### Additional implicit remap (extension of plan's sed step)

The plan's `sed` step covered `@/shadcn-components/ui/` and `@/shadcn-lib/utils` but missed `approval-card.tsx`'s `@/features/liv-ai/redact-args` import. Extended the sed pass with one additional substitution `@/features/liv-ai/ → @/lib/liv-ai/`. Not tracked as a separate Rule deviation because it is the natural extension of the path-remap intent stated in the plan's Task 2 ("imports inside tool-renderers.tsx" remap — same pattern applied here).
