# Phase 203 — Liv AI on openclaw-os + Desktop App Integration

## Why this phase

Phase 197–202 stacked four layers on top of each other — Mastra Agent/Memory/Mcp, then assistant-ui in a Next.js iframe, then a multi-agent platform, then OpenUI Lang generative UI. The operator wants to collapse the whole pile onto a single proven open-source surface (`openclaw-os` + `openclaw` gateway), which already ships the chat surface, tool dispatch, OpenUI app authoring, and the renderer — verified MIT on npm (`openclaw@2026.5.20`, `@openuidev/openclaw-os-plugin@0.1.5`). Mastra and assistant-ui become redundant and are removed in their entirety. On top of the upstream feature set, the operator wants ONE new capability: every OpenUI app produced via `app_create` should ALSO appear on the LivOS desktop as a real native-app icon, so clicking it opens a window mounting that OpenUI app — "as if we are literally generating apps."

## Phase Boundary

**IN SCOPE**

- L0 spike: clone `thesysdev/openclaw-os` locally on Windows, `npm i openclaw@^2026.5.20`, build, boot the gateway, observe exactly how LLM dispatch is wired (built-in inside the gateway, or delegated to a backend?). Output: a decision matrix for Plan 203-07.
- Full clone of `thesysdev/openclaw-os` into `livos/packages/liv-claw-os/` + rebrand pass (all user-visible strings: page title, breadcrumb, prompts/, SKILL.md, notifications, command palette, error messages → "Liv AI"). No functional code changes during rebrand.
- New systemd units on Mini PC: `liv-claw-gateway.service` (port 18789) + `liv-claw-plugin.service` (worker).
- Caddy: replace `handle /liv-ai-app/* → :3010` with `handle /liv-ai-app/* → :18789` (openclaw gateway serves the rebranded UI). All other handles untouched.
- Clone + rebrand the `@openuidev/openclaw-os-plugin` package into `livos/packages/liv-claw-plugin/` and reshape its `app_create` / `artifact` / `db_query` tool implementations so they call livinityd HTTP instead of writing JSON files. New Postgres table `livos_openui_apps` + new tRPC namespace `openclawos.apps.*`.
- WebSocket auth shim — livinityd issues a short-lived openclaw device token after verifying the LIVINITY_SESSION JWT cookie (parent UI → iframe handshake). Ed25519 device identity stays internal-only between the gateway and the claw-client.
- Luse MCP server (Phase 201 fix) preserved as-is; its 9 luse_* tools + 11 Phase 202-08 built-in tools (weather, get_current_time, ui_render, 8 existing) re-registered as openclaw gateway tools via `liv-claw-plugin`'s tool registry, proxying to livinityd. ApprovalManager HITL gate fires via RPC for destructive tools.
- Agent runtime swap — outcome decided by 203-01 spike. If openclaw has built-in LLM dispatch: `LivOSMastra` → `LivOSAgent` thin wrapper around the openclaw client. If openclaw delegates: install LangGraph.js in livinityd + write `LivOSAgent` to replace Mastra.
- Full Mastra purge — all `@mastra/*` deps removed from `livos/packages/livinityd/package.json`. `LivOSMastra` class deleted; `LivOSAgent` takes its place. AgentRegistry + AgentScheduler + agent-factory rewired to the new runtime.
- Full assistant-ui purge — `@assistant-ui/react`, `@assistant-ui/react-ai-sdk`, `@assistant-ui/react-markdown` removed from `livos/packages/liv-ai-app/package.json`. `app/assistant.tsx`, `components/assistant-ui/*`, `app/page.tsx` Liv AI thread, tool-renderers + openui-renderer DELETED. Phase 202 `/agents`, `/agents/[id]`, `/agents/new`, `/settings` routes KEPT (they're native fetch + tRPC, not assistant-ui dependent).
- **NEW (D-203-10) — Desktop integration:** when `app_create` fires successfully, livinityd inserts the app into the existing `liv:apps:native:<uuid>` registry consumed by the LivOS dock (`livos/packages/livinityd/source/modules/apps/native-app-config.ts`). Dock auto-refreshes via an SSE channel `/dock/refresh`. Window-body for an OpenUI app = `<iframe src="/liv-ai-app/apps/{slug}">`. The iframe renders ONLY the OpenUI markup via the in-repo OpenUI renderer (no chat surface).
- New route `/liv-ai-app/apps/[slug]` inside the rebranded openclaw-os Next.js UI — a standalone OpenUI app page (no thread, no composer).
- Mini PC deploy via `bash /opt/livos/update.sh` patched for the new units + new package install + Caddy rewrite + Postgres migration.
- 13-step VERIFICATION.md operator UAT walk template.

**OUT OF SCOPE (defer)**

- Per-user OpenUI apps (every app in v203 is admin-owned; per-user apps = Phase 220+).
- Agent-emitted custom icon URL in `app_create` args (placeholder SVG only in v203; custom icons = v204+).
- OpenUI app marketplace / sharing (v203 keeps apps local to the Mini PC).
- Multi-user iframe isolation (single admin user only in v203; same as Phase 202).
- Hot-reload of MCP servers (v203 keeps Phase 202-07 "restart-required" semantics).
- External telemetry backend (still console export only, carry-over from Phase 202).
- Distributed gateway (single-instance `liv-claw-gateway.service` only).
- Voice mode / PDF attachment adapter / title generation (Phase 202 carry-overs unchanged).
- LangGraph subgraph editor UI (if 203-07 picks LangGraph, the UI editor is Phase 220+).

## Threat Model

| ID | Threat | Mitigation |
|----|--------|------------|
| T-203-01 | openclaw gateway crash → chat surface fully down | systemd `Restart=on-failure RestartSec=5`; livinityd healthcheck on `:18789/health`; LivOS dock shows "Liv AI offline" badge when health probe fails |
| T-203-02 | Ed25519 device token reuse / replay | Token TTL = 5 min; livinityd issues a fresh token on each `/openclawos/handshake` call; openclaw gateway validates per-session and refuses re-use |
| T-203-03 | OpenUI markup XSS in desktop window | OpenUI renderer enforces the 14-component whitelist + `isSafeUrl()` allow-list (https://, root-relative, fragment, `data:image/*`); livinityd validates the same whitelist BEFORE persisting via `openclawos.apps.create`; rejects `<script>`/`javascript:`/`data:text/html` |
| T-203-04 | Mastra removal breaks running cron jobs at restart | Drain phase in Plan 203-08: scheduler tasks paused via `AgentScheduler.pauseAll()`, agents migrated to the new runtime via `registry.refresh()`, then `AgentScheduler.resumeAll()` |
| T-203-05 | Desktop dock auto-refresh race when many apps created in quick succession | Debounce dock refresh 500 ms client-side; `NativeAppConfigStore.upsert` is idempotent on duplicate uuid; SSE `/dock/refresh` carries no payload (clients re-fetch) |
| T-203-06 | Iframe-in-iframe (LivOS UI → liv-ai-app → openclaw client) trust chain | Same-origin throughout (`bruce.livinity.io`); CSP allows `frame-ancestors 'self'`; LIVINITY_SESSION cookie travels (`SameSite=Lax`); openclaw gateway hardens X-Frame-Options to SAMEORIGIN |
| T-203-07 | OpenUI app content can call `db_query` against livinityd Postgres | `db_query` tool wired through a read-only PG pool guard (separate role `livos_openui_ro` with `GRANT SELECT` only); tool restricted server-side to `SELECT` statements; per-user namespace filter `WHERE user_id = $session_user` injected |
