<objective>
Fix livinityd's App Gateway middleware so requests to `<app>.<domain>` (e.g. `n8n.test.livinity.live`) are proxied to the per-app container (e.g. `127.0.0.1:5678`) on fresh hybrid-mode installs.

Root-cause hypothesis (to be verified by Task 1's live evidence — but heavily supported by the static read already done at planning time): the gateway at `livos/packages/livinityd/source/modules/server/index.ts:315-324` short-circuits with `return next()` when `livos:domain:config` is missing or `active=false`. On a fresh `install.sh --mode hybrid` run, NO codepath writes `livos:domain:config` — only the manual Settings wizard (`domain.routes.ts setDomain/activate`) or the Livinity tunnel auto-bootstrap (`tunnel-client.ts:450-462`) do. So the gateway never fires even though `livos:domain:subdomains` contains the n8n entry, and livinityd's own UI HTML is served at every subdomain.

Purpose: closes the v34 App Store end-to-end loop. Without this fix, every WebApp install ends in "container running but browser can't reach it".

Output:
- `112-01-INVESTIGATION.md` with the concrete root cause (file:line + Redis key evidence)
- `_dld_seed_domain_config` helper in `deploy-livinityd.sh` (writes `livos:domain:config` from `livos:domain:hybrid_subdomain` / `livos:domain:tunnel_domain` during install, idempotent EXISTS short-circuit, WARN-not-FAIL)
- Defensive startup-time fallback at the top of the gateway middleware OR in livinityd's `start()` boot path (chosen in Task 2)
- +5 regression assertions in `test-deploy-livinityd.sh`
- Mainserver `154.53.56.75` live UAT proving `curl -H "Host: n8n.test.livinity.live" http://127.0.0.1:8080` returns n8n's response, not livinityd's
</objective>

        # 1. Read REDIS_URL from .env (already written by _dld_write_env_file).
        local redis_url=""

        local local_mode

                # the gateway's main-domain check works equally well on the bare TLD because
                # subdomains under it match the same suffix-check pattern.
                domain=$(redis-cli -a "$redis_pass" --no-auth-warning GET livos:domain:local_tld 2>/dev/null || echo "")
                ;;
            cloud|"")
                info "local_mode='${local_mode:-unset}' — no domain to seed, skipping (cloud mode has no subdomain routing)"
                return 0
                ;;
            *)
                warn "Unknown local_mode='${local_mode}' — skipping domain-config seed"
                return 0
                ;;

            return 0
        fi

        # livos/packages/livinityd/source/modules/domain/routes.ts:27-31.
        local activated_at

        local json
        json=$(printf '{"domain":"%s","active":true,"activatedAt":%s,"source":"install-112"}' \
            "$domain" "$activated_at")

        if ! redis-cli -a "$redis_pass" --no-auth-warning SET livos:domain:config "$json" >/dev/null 2>&1; then

            warn "livos:domain:config not present after SET — install continues"
            return 0
        fi

        ok "Seeded livos:domain:config domain=${domain} active=true source=install-112"
    }
