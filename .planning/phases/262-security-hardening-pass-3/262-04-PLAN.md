<objective>
WS4 — Re-classify the new Settings backends + cred-egress isolation.

Closes: **LIVOS-048 (High)** non-admin `system.restart`/`system.shutdown` (mgmt-plane DoS +
power-off); **LIVOS-050 (Medium)** any user can `formatExternalDevice` an arbitrary block device
incl. the OS disk (unvalidated `deviceId`); **LIVOS-051 (Medium)** `addNetworkShare` CIFS
mount-option injection + arbitrary-host SMB SSRF; **LIVOS-056 (Low)** `unmount`/`removeNetworkShare`/
samba toggles/`sharePassword`-secret reachable by any user; **LIVOS-046 (High)** cred-egress proxy
authenticates by docker-bridge source IP only → any container borrows the operator's OAuth
subscription.

Purpose: privileged host-control + storage + cred-egress operations become admin-only and
input-validated server-side (these routes are reachable from the Files app too, not just Settings),
and the cred proxy gains a per-app identity instead of trusting the whole bridge.

13129 is operator WS6). Backend = tsx, no build. Only NEW tsc errors block (~TS18048 baseline).
