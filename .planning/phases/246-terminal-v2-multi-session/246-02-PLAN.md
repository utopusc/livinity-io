<objective>
Build the Redis scrollback ring buffer module. Phase 243 already writes session metadata as a Redis HASH at `livos:pty:session:<id>`; this plan adds a sibling LIST at `livos:pty:session:<id>:scrollback` for capturing every PTY output chunk so reattach (246-03) can replay it.

Purpose: D-V44-TERMINAL-SCROLLBACK-RING locks the design at "10000-line Redis ring per session." This module is the **only** code path that touches the scrollback list — 246-03's WS handler imports `appendScrollback` on every PTY data event and `readScrollback` on the reattach branch. 246-05's GC imports `deleteScrollback` to drain dead sessions.

Also adds `touchLastAttachAt` — a one-field HSET against the EXISTING `livos:pty:session:<id>` hash key written by Phase 243's `writeSessionMetadata`. The TTL GC in 246-05 reads this field to decide whether a session is idle > 24h.

The module is **stateless** — every function takes a redis client. No singletons. Mirrors Phase 243's `metadata.ts` DI shape.

    ```ts
    /**
     * Phase 246-02 — Redis scrollback ring buffer + lastAttachAt persistence.
     *
     * Per D-V44-TERMINAL-SCROLLBACK-RING:
     *   - Per-session LIST at `livos:pty:session:<id>:scrollback`
     *   - LTRIM to 10000 most-recent lines after every RPUSH
     *
     * Per 246-CONTEXT (Reload-survive reattach):
     *   - `touchLastAttachAt` updates the HASH field on the EXISTING metadata key
     *     written by Phase 243's writeSessionMetadata.
     */

    import {PTY_SESSION_REDIS_PREFIX} from './metadata.js'

    export const PTY_SESSION_SCROLLBACK_SUFFIX = ':scrollback'
    export const SCROLLBACK_MAX_LINES = 10000

    export interface PtyScrollbackRedisClient {
      rpush(key: string, value: string): Promise<number>
      ltrim(key: string, start: number, stop: number): Promise<'OK' | string>
      lrange(key: string, start: number, stop: number): Promise<string[]>
      del(key: string): Promise<number>
      hset(key: string, field: string, value: string): Promise<number>
    }

    export function buildScrollbackKey(sessionId: string): string {
      return PTY_SESSION_REDIS_PREFIX + sessionId + PTY_SESSION_SCROLLBACK_SUFFIX
    }

    export async function appendScrollback(
      redis: PtyScrollbackRedisClient,
      sessionId: string,
      chunk: string,
    ): Promise<void> {
      const key = buildScrollbackKey(sessionId)
      await redis.rpush(key, chunk)
      await redis.ltrim(key, -SCROLLBACK_MAX_LINES, -1)
    }

    export async function readScrollback(
      redis: PtyScrollbackRedisClient,
      sessionId: string,
    ): Promise<string[]> {
      return redis.lrange(buildScrollbackKey(sessionId), 0, -1)
    }

    export async function deleteScrollback(
      redis: PtyScrollbackRedisClient,
      sessionId: string,
    ): Promise<void> {
      await redis.del(buildScrollbackKey(sessionId))
    }

    export async function touchLastAttachAt(
      redis: PtyScrollbackRedisClient,
      sessionId: string,
      isoTimestamp: string,
    ): Promise<void> {
      await redis.hset(PTY_SESSION_REDIS_PREFIX + sessionId, 'lastAttachAt', isoTimestamp)
    }
    ```

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-246-02-01 | I (Info disclosure) | scrollback persisted in Redis | accept | Shell output may contain secrets (env dumps, password prompts). Same trust model as Phase 243's bash history. Operator-controlled environment. Deferred: secret redaction is v45+ feature. |
| T-246-02-02 | D (DoS) | unbounded RPUSH from PTY flood | mitigate | LTRIM after every RPUSH caps the LIST at 10000 entries (SCROLLBACK_MAX_LINES drift-lock). Memory bound: 10000 × ~1KB/line max = ~10MB per session worst case. |
| T-246-02-03 | T (Tampering) | Redis key namespace collision | mitigate | All writes go through `buildScrollbackKey()` which composes the locked prefix `livos:pty:session:` + sessionId + `:scrollback`. sessionId is uuidv7 (unguessable), so external callers cannot target a key. |
| T-246-02-04 | R (Repudiation) | lastAttachAt overwrites are not audited | accept | Single-writer (the WS handler in 246-03) — operator-controlled deployment. Audit log is journalctl on livinityd. |
| T-246-02-05 | I (Info disclosure) | readScrollback called by an unauthenticated party | mitigate | This module's callers are ALL gated by 243-02's cookie auth + feature flag. The module itself does NOT enforce auth — that is the caller's contract. |
