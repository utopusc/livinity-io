<objective>
Extend the v43 WS handler to support multi-session create/attach/list semantics. This is the wave-2 integration plan — it glues 246-01's SessionManager and 246-02's scrollback ring into a single connection-aware protocol.

Purpose:
1. **Backward compat:** existing `/livos/terminal/ws` (no query) keeps working identically to Phase 243 — single PtySession per WS, no scrollback persistence required, no SessionManager registration. Phase 243's 13 ws-handler tests stay GREEN.

   Wait — that's a contradiction with multi-session goals. RESOLUTION per CONTEXT "Backward compat preserved": the **endpoint path** is preserved. The behavior is upgraded — every WS now routes through SessionManager. The no-query default becomes equivalent to `?create`. Phase 243's 13 tests still pass because they assert on the visible protocol (init→ready, data, exit) which is unchanged. New scrollback writes are tested via NEW cases, not by modifying the 243 cases.

2. **`?create` path (default):** Mint a new session via SessionManager.create(opts), wire up data forwarding with scrollback persistence, behave like Phase 243 from then on.

3. **`?attach=<id>` path:** Lookup SessionManager.get(id). If null → close 4404. If found:
   - Send `{type:'reattached', sessionId, scrollback: [...]}` (single frame; scrollback as a string array — client concatenates)
   - Call `touchLastAttachAt(redis, id, now)` + `sessionManager.touch(id)`
   - Resume forwarding pty.on('data') → ws.send + appendScrollback (same as create path)
   - Client init message is OPTIONAL on reattach (cols/rows resize can come later via {type:'resize'})

4. **`?list` path:** EXPERIMENT — actually NOT used by the UI in v44 because the admin list goes through tRPC. Remove `?list` from scope; the WS handler only does create/attach. List is tRPC.

5. **Survives reload contract:** WS close NO LONGER auto-kills the PTY. Only explicit `{type:'close'}` client message OR `sessionManager.kill()` (called by admin or TTL GC) destroys the PtySession. This is the semantic break from Phase 243 — the v43 cleanup auto-killed on ws.close.

6. **Admin tRPC router:** new file `admin-router.ts` with two procedures (`listSessions`, `killSession`). Mounted under `pty-sessions` namespace in the main app router (see Task 3 server wiring). Uses `adminProcedure` (the v7.0 RBAC primitive, per MEMORY).
