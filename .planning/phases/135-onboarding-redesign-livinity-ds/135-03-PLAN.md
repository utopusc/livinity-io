# Plan 135-03 — Setup Wizard Core Redesign (`setup-wizard.tsx`, 1402 LOC)

**Wave:** 2 (parallel with 135-02 — different file)
**Autonomous:** true
**Sacred SHA invariant:** preserved

## What

Redesign `livos/packages/ui/src/routes/onboarding/setup-wizard.tsx` (1402 LOC, the MAIN flow). This is the biggest sub-plan. Multi-step interactive flow:
1. **Language** picker (or auto-detect)
2. **Mode picker** — cloud / hybrid / tunnel / local-lan
3. **Per-mode specific configuration** — different paths per mode
4. **Confirmation + apply** — final summary + start install / activate

Re-skin to DS tokens **without** changing the flow logic. Every state transition, every tRPC call, every form validator stays as-is.

## Approach (since file is large)

1. **Read the file top-to-bottom** to map each step's JSX.
2. **Identify visual primitives** used (Card, Button, Input, Select, Stepper, ProgressBar). Build a list.
3. **Build DS-aware variants** of each primitive (or use existing shadcn components if they're already neutral enough).
4. **Replace primitives one-by-one**, verifying each at localhost:3000.
5. **Do not refactor business logic** — only swap JSX wrappers + classNames.

## Files touched

Primary:
- `livos/packages/ui/src/routes/onboarding/setup-wizard.tsx`

Possibly:
- Subset of `src/shadcn-components/*` if their default theme conflicts with DS tokens. Prefer to override via `data-flow="onboarding"` scope rather than mutating shadcn primitives — keeps the rest of the app unaffected.

## How (step-by-step skeleton)

### Step 0: Reconnaissance (15 min)

```
Read setup-wizard.tsx with offset/limit pagination.
Map the major sections:
  - Top-level state machine (which React state holds current step)
  - Per-step components (inline or extracted?)
  - i18n keys used
  - tRPC mutation/query usage
```

Record findings as comments in this plan during execution.

### Step 1: Build DS step-shell (30 min)

Create a reusable `WizardStep` component:
```tsx
function WizardStep({
    title, subtitle, currentStep, totalSteps, onBack, onNext, nextDisabled, children,
}) {
    return (
        <div className="liv-card" style={{display: 'flex', flexDirection: 'column', gap: 24}}>
            <DsStepIndicator current={currentStep} total={totalSteps} />
            <header>
                <h1 style={{fontSize: 28, fontWeight: 600}}>{title}</h1>
                {subtitle && <p style={{color: 'var(--liv-fg-mute)'}}>{subtitle}</p>}
            </header>
            <div>{children}</div>
            <footer style={{display: 'flex', justifyContent: 'space-between'}}>
                <button className="liv-btn-secondary" onClick={onBack}>Back</button>
                <button className="liv-btn" disabled={nextDisabled} onClick={onNext}>Next</button>
            </footer>
        </div>
    )
}
```

### Step 2: Replace existing step renderers with `WizardStep` (60-90 min)

Walk each step's JSX, swap the outer wrapper to `WizardStep`, keep inner form fields untouched (unless their styling is gradient-based).

### Step 3: Re-skin form fields (30 min)

Inputs, selects, radios — wrap in `<label>` blocks with DS-aware label colors (`--liv-fg-dim`) and DS-aware input borders (`--liv-line-strong`). Or use shadcn `<Input>` with `data-flow="onboarding"` ancestor providing the override.

### Step 4: Mode-pick cards (30 min)

The mode picker (cloud / hybrid / tunnel / local-lan) is conceptually 4 cards. Re-style as horizontal radio-card list:
- Selected: `border-color: var(--liv-fg)`, slight `background: var(--liv-accent-soft)`
- Unselected: `border-color: var(--liv-line)`, hover `border-color: var(--liv-line-strong)`

### Step 5: Test each step at localhost:3000 (operator-walked)

Walk:
1. Open `localhost:3000/onboarding` in browser
2. Click through each step
3. Verify visual matches DS aesthetic + no regressions
4. Operator confirms before merge

### Step 6: Commit (atomic)

One commit for the whole setup-wizard redesign. Diff will be large (~400 net) but contained to one file.
