<objective>
Deliver D-131-E tier (b) — pinned windows keep running on the server when the user closes the browser tab. The UI is just a viewer; the actual session host is livinityd.

This is the hardest plan in Phase 131. Cannot start until `/gsd-discuss-phase 131` locks:
- D-131-B (Service Worker vs livinityd host) — default proposal: livinityd
- D-131-C (per-app vs generic session contract) — default proposal: per-app

Per-app session hosts (assuming D-131-C = per-app):
- **WebApp**: livinityd already manages the Chrome handle via bytebot. Just hold the handle past the WebSocket disconnect + tear down on GC tick.
- **AI Chat**: livinityd already runs hermes for AI sessions (v32). Pinning a conversation just means "don't tear down on disconnect". Hermes already supports re-attach.
- **Files**: stateless mostly. Watcher subscription needs to survive disconnect. Trivial.

UI side: when a chip is clicked, the `unpinWindowFromTopBar` call sends a "re-attach" request via WebSocket; livinityd streams the current snapshot + a live event stream back; the React window re-renders the current state.

Output:
- `livos/packages/livinityd/source/modules/pinned-sessions/` directory with the host implementations.
- Per-app contracts documented in 131-03-SUMMARY.md.
- WebSocket reconnect protocol documented (existing project uses native WebSocket + tRPC; this plan extends the agent-stream channel pattern).
- UAT proving tab-close-survives for at least one app type.
</objective>

Create `livos/packages/livinityd/source/modules/pinned-sessions/` directory with:

Interface (assuming D-131-C = per-app):
```ts
export interface PinnedSession {
  readonly windowId: string
  readonly appId: string
  /** Called when the first client attaches. Spawns the underlying app session. */
  hydrate(payload: unknown): Promise<void>
  /** Called when the last client detaches. Optional teardown (default: no-op, keep running). */
  freeze?(): Promise<void>
  /** Returns a snapshot of the session's current visual + logical state for re-attach. */
  snapshot(): Promise<unknown>
  /** Live event stream to the attached client (UI). */
  subscribe(callback: (event: unknown) => void): () => void
  /** Tear down — used by GC or explicit unpin. */
  dispose(): Promise<void>
}
```

The registry's GC tick: every 1h, drop sessions with `last_seen_at` older than 24h (read from the `pinned_windows` Postgres row).

<task id="03-03" type="execute">
<action>
**UI re-attach wiring.**

When the user clicks a pinned chip:
1. `unpinWindowFromTopBar(windowId)` dispatches the React state change (window animates back).
2. The window's `WindowContent` mounts and calls `trpc.pinnedSessions.attach.mutate({windowId})`.
3. The mutation returns the snapshot + opens a subscription channel.
4. The window re-renders with the snapshot, then plays the live event stream as if the user had never left.

When the user pins:
1. `pinWindowToTopBar` upserts to Postgres (Plan 131-02 already wired).
2. Send `trpc.pinnedSessions.persist.mutate({windowId, currentState})` to freeze the session on the server.
3. UI shrinks to chip (Plan 130-09 animation).

When the tab closes:
- Browser fires `beforeunload`. Send a final `trpc.pinnedSessions.detach.mutate({windowId})` for each pinned window (best-effort — sendBeacon if available).
- livinityd keeps the session running (no `dispose()` call), waits for a re-attach.
</action>
