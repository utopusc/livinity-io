<objective>
Once pinned windows live in livinityd (Plan 131-03), expose them as MCP tools so AI agents can read + control them via the broker subscription path. Per D-131-D = MCP.

The agent loop already supports MCP servers (Phase 77 carry-over: `additionalMcpServers` in SdkAgentRunner, MCP child process spawn). This plan registers a new MCP server `livos-pinned-windows` that exposes:

- `list-pinned-windows` → array of {id, appId, title, route}
- `read-pinned-window <id>` → snapshot (screenshot for WebApp, message log for AI Chat, current path for Files)
- `send-input-to-pinned <id> <event>` → keyboard/mouse/text event
- `wait-for-pinned <id> <predicate>` → block until condition (with timeout)

Threat model (BLOCKING):
- Rate limit: max 60 ops/min per pinned window. Per-user soft cap 600 ops/min across all pins.
- Allowlist: user must explicitly enable AI control per pinned window (default OFF). UI affordance in Plan 131-05.
- Input sanitization: send-input rejects shell-style metacharacters in text mode for non-WebApp targets.
- Audit log: every AI op writes to a `pinned_window_audit` table (windowId, op, agent_id, at).
</objective>

  id           BIGSERIAL    PRIMARY KEY,
