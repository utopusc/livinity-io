# Phase 273 Plan 01 — Update safety Layer-B

<objective>
Add an independent, SIGKILL-immune rollback guard to update.sh: a `systemd-run` transient unit (in system.slice) armed before the risky `systemctl restart livos.service`, disarmed by update.sh's EXIT trap, that — only if update.sh died without disarming (SIGKILL) — restores `/opt/.livos-last-good`, restarts, and writes a `failed.json`. Self-contained heredoc guard script; race-safe via the shared flock; safe-or-better (never disturbs a healthy box). All in `update.sh`.
</objective>

<must_haves>
- A heredoc-installed standalone guard at `/opt/livos/livos-deploy-guard.sh` (idempotent `install_deploy_guard()`), self-contained: own restore + :8080 probe + failed.json writer (it runs after update.sh is dead).
- `arm_deploy_guard()` called right before `systemctl restart livos.service`: writes the `/opt/livos/data/update/deploy-inflight` sentinel (deploy-id + from/to sha + log_path + iso) and `systemd-run --slice=system.slice --collect --on-active=300 --unit=livos-deploy-guard /opt/livos/livos-deploy-guard.sh <deploy-id>`. Fail-open (no systemd-run → warn, skip).
- `disarm_deploy_guard()` called at the TOP of `phase33_finalize` (EXIT trap): stop+reset-failed the `livos-deploy-guard.{timer,service}` units + delete the sentinel.
- Guard logic: acquire `flock -n` on `/run/lock/livos-update.lock` (can't → update.sh alive → no-op); sentinel absent or deploy-id mismatch → no-op+cleanup; probe :8080 for ~60-90s → healthy → no-op+cleanup; unhealthy → restore `/opt/.livos-last-good` + reset-failed + restart + re-probe + write `<iso>-failed.json` to update-history + cleanup. Fires once. No rollback loop.
- Kill-switch: `LIVOS_DISABLE_DEPLOY_GUARD=1` skips arming.
- `bash -n update.sh` clean; `bash -n` clean for the emitted guard script (extract + check).
</must_haves>

<action>
1. Add constants near LAST_GOOD_DIR (≈L346): `DEPLOY_GUARD_SCRIPT=/opt/livos/livos-deploy-guard.sh`, `DEPLOY_GUARD_SENTINEL=/opt/livos/data/update/deploy-inflight`, `DEPLOY_GUARD_UNIT=livos-deploy-guard`, `DEPLOY_GUARD_DELAY=300`.
2. `install_deploy_guard()` — heredoc-write the standalone guard to `$DEPLOY_GUARD_SCRIPT` (chmod +x), idempotent (mirror ensure_livos_killmode_dropin). The guard script:
   - `exec 9>/run/lock/livos-update.lock; flock -n 9 || exit 0` (update.sh still alive → bail).
   - read `$1` (expected deploy-id); read sentinel; if missing or id mismatch → rm sentinel (if mismatch leave it) → exit 0.
   - probe `http://127.0.0.1:8080/` (accept 2xx/3xx/401/403) for ~60-90s (e.g. 20×4s). healthy → rm sentinel → exit 0.
   - unhealthy → restore `/opt/.livos-last-good` (livinityd-source + ui-dist + symlink + liv-core dist + pnpm-store propagation + chown bruce) → `systemctl reset-failed livos.service` → `systemctl restart livos.service` → re-probe ~120s → write `${HISTORY_DIR}/<sentinel-iso-fs>-failed.json` (status failed, reason "Layer-B guard rolled back a stranded/broken deploy", from/to sha, log_path from sentinel) → rm sentinel.
   - All best-effort / `2>/dev/null || true`; never exit non-zero in a way that latches the transient unit failed (use `exit 0` at the end).
3. `arm_deploy_guard()`:
   - honor `LIVOS_DISABLE_DEPLOY_GUARD` → warn + return.
   - `command -v systemd-run` else warn + return (fail-open; Layer-A still protects).
   - stop any stale `${DEPLOY_GUARD_UNIT}.{timer,service}` + reset-failed.
   - `install_deploy_guard`.
   - `mkdir -p $(dirname sentinel)`; write sentinel with deploy-id=`$LIVOS_UPDATE_START_TS`, iso_fs=`$LIVOS_UPDATE_START_ISO_FS`, iso_json, from_sha=`$LIVOS_UPDATE_FROM_SHA`, to_sha=`$LIVOS_UPDATE_TO_SHA`, log_path.
   - `systemd-run --slice=system.slice --collect --on-active=${DEPLOY_GUARD_DELAY} --unit=${DEPLOY_GUARD_UNIT} -- ${DEPLOY_GUARD_SCRIPT} "$LIVOS_UPDATE_START_TS"` (2>/dev/null; warn on failure but continue).
4. `disarm_deploy_guard()`: `systemctl stop ${DEPLOY_GUARD_UNIT}.timer ${DEPLOY_GUARD_UNIT}.service 2>/dev/null; systemctl reset-failed ${DEPLOY_GUARD_UNIT}.* 2>/dev/null; rm -f "$DEPLOY_GUARD_SENTINEL"`. All best-effort.
5. Wire: call `disarm_deploy_guard` as the FIRST statement inside `phase33_finalize()` (before it reads exit_code is fine — capture exit_code first, then disarm). Call `arm_deploy_guard` right before `systemctl restart livos.service` (after `ensure_livos_killmode_dropin`, ≈L1848). NOTE: `LIVOS_UPDATE_TO_SHA` must be set before arming — confirm it is (it's set when the SHA is resolved); if not yet set at arm time, the sentinel's to_sha may be empty (acceptable — failed.json tolerates empty to_sha).
6. Verify: `bash -n update.sh`. Extract the heredoc'd guard body to a temp file and `bash -n` it too.
</action>
