<objective>
**Decouple `sessionCwd` from `computerUse`** in `agent-session.ts:444-449` so
surface vault paths thread through to the SDK `query()` `cwd` option for
BOTH Main Chat AND computer-use sessions. This is the BLOCKER #1 fix from the
163 plan-checker review.

**Why this matters:** Phase 163-02 (ws-agent.ts) builds per-session
`AgentSessionManager` instances pinned to surface vault paths
(`/home/bruce/livinity-vault/surfaces/webapp/<id>`). But the existing Phase
162-02 derivation block has:

```ts
const vaultMode = !computerUse && this.vaultModeConfig !== null;
const sessionCwd = vaultMode ? this.vaultModeConfig!.vaultPath : undefined;
```

For `conversationId: 'webapp:suna:uuid'`, `isComputerUseSession === true`, so
`vaultMode = false`, so `sessionCwd = undefined`. **The per-session manager's
carefully resolved surface vaultPath is silently discarded.** Phase 163 ships
broken without this fix — WebApp/Native chats receive no surface CWD.

**The fix splits the gate into TWO derivations:**

1. **CWD gate** (new): `vaultMode = this.vaultModeConfig !== null` — computerUse
   is NO LONGER part of this gate. Any time vaultModeConfig is set, `cwd` flows
   through.
2. **Overlay gate** (preserved Phase 162-02 behavior): `systemPrompt` and
   `settingSources` continue using `vaultMode && !computerUse` so computer-use
   STILL uses the Phase 161-02 LivOS overlay via `systemPrompt`, and computer-
   use does NOT auto-load vault skills/commands (the overlay is sufficient).

**Result matrix after this plan:**

| vaultModeConfig | computerUse | systemPrompt | cwd | settingSources | model |
|---|---|---|---|---|---|
| set | true (webapp:/native:) | builder() | vaultPath (NEW) | undefined | Haiku 4.5 dated |
| set | false (Main Chat) | undefined | vaultPath | ['project'] | defaultModel |
| null | true | builder() | undefined | undefined | Haiku 4.5 dated (Phase 161) |
| null | false | <BASE> | undefined | undefined | tierToModel(tier) (Phase 161) |

Output: One MOD to `agent-session.ts` (split derivation) + updated vault-mode
test file (new derivation source-text invariant + new Test 14 for the
post-163-02.5 matrix).
