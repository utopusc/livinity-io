<objective>
Eliminate the #1 amateur tell: today `use-terminal-ws.ts` has NO reconnect — `onclose` writes `[disconnected]` and the pane is dead. Add resilient reconnect-with-scrollback + a thin bottom status bar.

This plan:
1. Extends `useTerminalWs` with bounded exponential-backoff auto-reconnect (1s→2s→4s→8s cap, ~3 tries then manual Retry) that REUSES the session id — firing the existing `?attach=<id>` reattach + Redis scrollback replay into the SAME Terminal instance (never a second div).
2. Distinguishes close codes: **4404** (TTL GC / unknown session) → no retry, route to existing `onExpired`; **transient drop** → dim pane + centered "Reconnecting… (n)" chip + "Reconnected" flash on success.
3. Adds `TerminalStatusBar.tsx` — connection pill off WS `readyState`, cols×rows-on-resize (~300ms fade), `user@host` / session id, optional OSC title via `onTitleChange`.

Purpose: honest connection feedback; reload + transient-drop survival becomes complete.
Output: reconnect logic in the hook + a new status bar component + tests.

**Reconnect correctness:** the reconnect MUST reuse the SAME `Terminal` instance and reattach by session id so the server's `{type:'reattached', scrollback}` replays into the existing buffer. Do NOT tear down/recreate the xterm or its DOM div on reconnect — only the WebSocket reopens. The session id is the one resolved on first `ready`/`reattached` (stash it).
