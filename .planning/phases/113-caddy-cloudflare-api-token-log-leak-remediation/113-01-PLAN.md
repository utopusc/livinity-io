<objective>
Stop Caddy systemd unit from logging plaintext `CLOUDFLARE_API_TOKEN` to journald on every reload. Currently anyone with root or `journalctl -u caddy` read access can recover the CF API token from logs — medium-severity credential leak.

Fix: Migrate the token from inline `Environment=CLOUDFLARE_API_TOKEN=...` to `EnvironmentFile=/etc/caddy/cloudflare.env` (chmod 600 root:root). systemd does NOT echo EnvironmentFile contents to journal.

Scope is mainserver `154.53.56.75` only — no source-tree code changes in this repo.
</objective>

<action>
Single SSH session to apply fix atomically + verify. Steps run in order:

```bash
/c/Windows/System32/OpenSSH/ssh.exe \
  -i C:/Users/hello/Desktop/Projects/contabo/pem/contabo_master \
  -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null \
  -o ConnectTimeout=15 \
  root@154.53.56.75 'bash -s' <<'REMOTE'
    set -e

    echo "=== 1. Extract current token from Environment= line ==="
    # Read current token from systemctl (avoids parsing unit files)
    CURRENT_TOKEN=$(systemctl show caddy --property=Environment | grep -oP 'CLOUDFLARE_API_TOKEN=\K[^ ]+' || true)
    if [ -z "$CURRENT_TOKEN" ]; then
      echo "FAIL: could not extract CLOUDFLARE_API_TOKEN from systemctl show caddy"
      exit 1
    fi
    echo "Token extracted (length=${#CURRENT_TOKEN})"

    echo "=== 2. Write EnvironmentFile (chmod 600 root:root) ==="
    install -m 600 -o root -g root /dev/null /etc/caddy/cloudflare.env
    printf "CLOUDFLARE_API_TOKEN=%s\n" "$CURRENT_TOKEN" > /etc/caddy/cloudflare.env
    chmod 600 /etc/caddy/cloudflare.env
    chown root:root /etc/caddy/cloudflare.env
    ls -la /etc/caddy/cloudflare.env

    echo "=== 3. Create systemd override to swap Environment= -> EnvironmentFile= ==="
    mkdir -p /etc/systemd/system/caddy.service.d
    cat > /etc/systemd/system/caddy.service.d/override.conf <<EOF
[Service]
# Phase 113: stop leaking CLOUDFLARE_API_TOKEN to journald.
# Reset the inline Environment= from base unit, then load from secured file.
Environment=
EnvironmentFile=/etc/caddy/cloudflare.env
EOF
    cat /etc/systemd/system/caddy.service.d/override.conf

    echo "=== 4. daemon-reload + graceful reload (no downtime) ==="
    systemctl daemon-reload
    systemctl reload caddy
    sleep 3
    systemctl is-active caddy

    echo "=== 5. Verify env var still resolves correctly ==="
    systemctl show caddy --property=EnvironmentFiles
    # Note: EnvironmentFile contents are NOT shown by systemctl show; that is the point.

    echo "=== 6. Verify journalctl is clean of plaintext token ==="
    # Force one more reload to generate a fresh journal entry under the new config
    systemctl reload caddy
    sleep 2
    LEAK_COUNT=$(journalctl -u caddy --since "30 seconds ago" 2>&1 | grep -ci "cloudflare_api_token" || true)
    echo "Plaintext token occurrences in last 30s of journal: ${LEAK_COUNT}"
    if [ "${LEAK_COUNT}" -gt 0 ]; then
      echo "FAIL: token still leaking after EnvironmentFile migration"
      journalctl -u caddy --since "30 seconds ago" | grep -i "cloudflare_api_token" | head -5
      exit 1
    fi
    echo "PASS: journalctl clean of CLOUDFLARE_API_TOKEN plaintext"

    echo "=== 7. Verify TLS still works (no DNS-01 disruption) ==="
    curl -sIL -m 10 https://test.livinity.live 2>&1 | head -3
    curl -sIL -m 10 https://n8n.test.livinity.live 2>&1 | head -3
    echo "Both root and wildcard subdomain still serve cert."

    echo "=== 8. Capture cert renewal state ==="
    ls -la /var/lib/caddy/.local/share/caddy/certificates/acme-v02.api.letsencrypt.org-directory/wildcard_.test.livinity.live/ 2>&1 | head -5
REMOTE
```

Save the full output to `.planning/phases/113-caddy-cloudflare-api-token-log-leak-remediation/113-01-DEPLOY.md`.
