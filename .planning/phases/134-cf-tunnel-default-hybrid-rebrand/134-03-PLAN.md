## Script contract

```
Usage: migrate-to-cf-tunnel.sh --domain DOMAIN --cf-tunnel-token TOKEN [--dry-run]

Migrates an existing LivOS install from direct-LAN hybrid (Caddy LE) to CF
Tunnel hybrid. Idempotent — safe to re-run.

Required:
  --domain            The domain already configured (e.g. bruce.livinity.live)
  --cf-tunnel-token   The CF Tunnel token (from livinity.io/dashboard/install
                      OR manually created in CF Zero Trust dashboard)

Optional:
  --dry-run           Print the steps that would run; make no changes
  --keep-le-cert      Don't delete /var/lib/caddy LE state (default: delete)
```

## Steps the script performs

1. **Pre-flight** — assert running as root, assert mode-tunnel.sh helpers reachable (either via repo or self-bootstrap), assert `--domain` + `--cf-tunnel-token` provided.
2. **Detect current mode** — read `livos:domain:local_mode` from Redis (using existing `set_livos_redis_key` helper pattern). Confirm `hybrid` (legacy) — abort if `tunnel` (already migrated) unless `--force`.
3. **Snapshot current state** — write `/var/lib/livos/migrate-134-snapshot.json` with current Caddyfile, Redis keys, A-record content. Allows post-mortem if migration breaks.
4. **Stop Caddy** — `systemctl stop caddy` (will be reconfigured for tunnel mode).
5. **Install cloudflared** — call `_install_cloudflared_for_tunnel` from `mode-tunnel.sh` (already idempotent).
6. **Write CF Tunnel token secret** — call `_write_cf_tunnel_token_secret`.
7. **Register cloudflared systemd** — call `_register_cloudflared_service`.
8. **Reconfigure Caddy** — call `_configure_caddy_for_tunnel` (HTTP-only :80, no TLS).
9. **Optionally delete LE state** — `rm -rf /var/lib/caddy/.local/share/caddy/certificates/acme*` (operator can disable with `--keep-le-cert`). Reduces config drift; LE certs become unused.
10. **Persist Redis migration markers** — call `_persist_tunnel_mode_redis` (`livos:domain:local_mode=tunnel`, `livos:domain:tunnel_domain=$DOMAIN`).
11. **Restart Caddy + livinityd** — `systemctl restart caddy livos`.
12. **Wait for cloudflared connection** — poll `cloudflared --version` is registered + `journalctl -u cloudflared --since "1 minute ago" | grep "Registered tunnel connection"` within 60s.
13. **Health check** — `curl -fsS https://$DOMAIN/ -o /dev/null -w "%{http_code}"` returns 200 within 30s.
14. **Verify sacred SHA** — `git hash-object /opt/liv/packages/core/src/sdk-agent-runner.ts` equals `f3538e1d…`. (Defensive: ensure migration didn't touch it.)
15. **Print summary** — show old vs new Redis state, log paths for journalctl, and the verification curl command.

## Idempotency

- Each step checks current state before mutating.
- Re-run after partial failure picks up from where it left off (e.g. cloudflared already installed → skip step 5).
- Step 9 (delete LE state) gated on `[[ ! -f /var/lib/livos/migrate-134-done ]]` so it only fires once.

## Failure modes + handling

| Failure | Behavior |
|---------|----------|
| cloudflared apt repo unreachable | abort, print manual install command, leave Caddy stopped + Redis untouched |
| Invalid CF Tunnel token | cloudflared service fails to start → script detects + prints "wrong token? regenerate at livinity.io/dashboard/install" |
| Caddy reload fails | restore from snapshot Caddyfile, restart Caddy |
| Health check timeout | print journalctl tail for cloudflared + livinityd, exit 1 |
| `livinityd` not active post-restart | `systemctl status livos` + `journalctl -u livos --since "1 minute ago"` printed for diagnosis |

## Rollback

The script snapshots state at step 3. A companion `rollback-migration-134.sh` would restore from snapshot, but for v1 scope a rollback is "manual: cat /var/lib/livos/migrate-134-snapshot.json | jq -r .caddyfile > /etc/caddy/Caddyfile && systemctl stop cloudflared && systemctl restart caddy".
