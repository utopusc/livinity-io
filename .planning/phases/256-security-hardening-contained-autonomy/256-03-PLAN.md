<objective>
WS-C — Pipeline Admin-Gate. Close LIVOS-007 (no host-path validation on per-user app compose volumes —
any marketplace app can mount arbitrary host paths incl. docker.sock) and LIVOS-013 (untrusted app-store
compose run verbatim — no filter of privileged/docker.sock/host-mount), plus the #1 residual (restrict
the privileged install pipeline to admin). Per the operator-locked decision: (a) restrict
`requiresLocalAiClis`, `requiresAiProvider`-with-creds, `apps.addRepository`, and install-of-new-non-builtin
apps to admin/verified-only; (b) strip `privileged`/`network_mode:host`/`pid:host`/`docker.sock`/arbitrary
host-path binds from any NON-BUILTIN compose — builtin apps keep their declared mounts. This is the
single highest-leverage change and unblocks nothing the operator currently does (curated installs are
admin anyway).

Purpose: a non-admin user (or an attacker-controlled marketplace repo) can no longer reach host root via
a crafted compose, and curated builtin apps (Portainer's deliberate docker.sock, OpenHands' accepted risk)
keep working untouched.
Output: a `compose-sanitizer.ts` that runs on the non-builtin install path, plus adminProcedure gates on
the privileged pipeline routes.

ORDERING / ALLOWLIST NOTE (cross-plan, revision fix F): WS-B (256-02) rewrites injectLocalAiClisConfig to
add operator-trusted mounts OUTSIDE appDataDir — the cred-proxy CA cert (`:ro`), the isolated glibc, the
host node binary, the claude-code/gemini-cli binaries, and the wrapper-bin (all under `CLI_MOUNT_PREFIX`
= `/opt/livos-clis`). The non-builtin sanitizer in this plan runs on the COMMUNITY-REPO compose path; for
`requiresLocalAiClis` apps the inject runs and adds those mounts. The sanitizer MUST run BEFORE the WS-B
inject (so it only ever sees the app-author's declared mounts, not the injected ones), OR carry an explicit
allowlist that permits host-side bind sources under `CLI_MOUNT_PREFIX` (`/opt/livos-clis`) and the cred-proxy
CA path. Otherwise it would falsely reject the operator-trusted CLI/CA inject paths and break OpenDesign.
Tasks 1 + 2 below encode this carve-out — do NOT strip the broker/CLI-injected mounts.
</objective>

<sanitizer_policy>
Reject (throw, abort install) OR strip on the non-builtin service object:
- `privileged: true`                       → strip (delete the key)
- `network_mode: host` / `pid: host` / `userns_mode: host` → strip
- `cap_add` (any)                          → strip
- `security_opt` containing `*unconfined`  → strip the unconfined entries
- volume binds whose HOST side is NOT under `${appDataDirectory}` (after realpath) → reject install
  (covers `/var/run/docker.sock`, `/`, `/opt/livos/data/users/<other>`, `~/.claude`, `/proc`, `/sys`)
  EXCEPT the WS-B operator-trusted inject paths under `CLI_MOUNT_PREFIX` (`/opt/livos-clis`) and the
  cred-proxy CA cert path — those are allowlisted (revision fix F). In practice the sanitizer runs on the
  app-author compose BEFORE the WS-B inject, so injected mounts are not present at sanitize time; the
  allowlist is a belt-and-suspenders guard in case ordering ever changes.
- always add `security_opt: [no-new-privileges:true]` to the sanitized service
Builtin + platform-DB composes: NOT sanitized (operator-curated; Portainer/OpenHands keep their mounts).
</sanitizer_policy>
