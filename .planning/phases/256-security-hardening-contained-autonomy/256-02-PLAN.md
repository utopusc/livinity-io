<objective>
WS-B — Credential Egress Proxy. Close LIVOS-001 (the operator's `~/.claude` / `~/.gemini` OAuth token
dirs are bind-mounted READ-WRITE into third-party app containers + ACL'd in, so any code in the
container can steal or overwrite the operator's paid-subscription tokens; the claimed UI consent gate
does not exist). Per the operator-locked decision and SECURITY-REMEDIATION-DESIGN.md Option A
(Infisical agent-vault / Cloudflare Sandbox model): STOP mounting the token dirs. Run a host-side
credential-injecting egress proxy that holds the tokens and injects the bearer at the wire; the
container receives `HTTPS_PROXY` + a placeholder key only — token theft AND token overwrite both become
impossible. This reuses the trust model the operator already runs in `inject-ai-provider.ts` +
`plugins/livinity-broker` (broker holds creds, container gets base-URL + sentinel, auth by source-IP +
URL-path) — the new piece is wire-level injection for OAuth subscriptions (which the API-key broker
cannot do).

Purpose: OpenDesign-class apps keep running the real claude/gemini CLIs with the operator's own auth,
but a compromised container can no longer exfiltrate or clobber the subscription tokens.
Output: a `cred-egress-proxy.ts` host service + its installer wiring, and an `inject-local-ai-clis.ts`
rewrite that drops the cred bind mounts in favor of proxy env injection.

NOTE (ToS caveat, carried from the design doc, not actioned here): routing third-party app inference
through the operator's PERSONAL subscription may violate provider ToS regardless of mechanism
(theregister.com 2026-02-20). The egress proxy is the right call for first-party / operator-trusted
apps (OpenDesign). The per-app metered-key path for untrusted marketplace apps is an explicit Deferred
Idea in 256-CONTEXT.md and is OUT of scope for this plan.
</objective>

<proxy_design_note>
The cred-egress-proxy is a host HTTP CONNECT proxy on a fixed loopback port (e.g. 13129), reachable by
the container as `livinity-credproxy:13129` via `extra_hosts: livinity-credproxy:host-gateway` (the same
mechanism inject-ai-provider already uses for livinity-broker). The CLIs make their normal HTTPS calls;
the proxy MITM-terminates only the allowlisted AI hosts (api.anthropic.com + Gemini host), reads the
operator's token from `~/.claude/.credentials.json` / `~/.gemini/oauth_creds.json` ON THE HOST, and
injects `Authorization: Bearer <real token>`. The container only ever holds the placeholder
`ANTHROPIC_API_KEY=__livinity_credproxy__`. For TLS interception the proxy ships a local CA whose cert is
mounted READ-ONLY into the container (the cert is public, not a secret) so the CLIs trust the
intercepted leg; the operator's private token never crosses the container boundary in either direction.
Source-IP gate: accept only the docker bridge subnet (mirrors the broker's source-IP guard).
</proxy_design_note>

|----------|-------------|
| third-party container → operator OAuth tokens | container code could read/overwrite ~/.claude / ~/.gemini |
| container → AI provider network | container makes HTTPS calls that must carry the operator's bearer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-256B-01 | Information Disclosure | token theft from mounted `~/.claude`/`~/.gemini` | mitigate | drop the bind mounts; tokens stay on host, injected at the wire (Task 1+2) |
| T-256B-02 | Tampering | token OVERWRITE via RW mount | mitigate | no cred mount + read-only token use in the proxy (Task 1+2) |
| T-256B-03 | Spoofing | non-AI host receiving the injected bearer | mitigate | isInjectableHost allowlist — bearer injected ONLY for AI hosts (Task 1) |
| T-256B-04 | Elevation / lateral | rogue source reaching the cred-proxy | mitigate | source-IP gate to the docker bridge subnet (Task 1) |
| T-256B-05 | ToS / Repudiation | untrusted app riding the personal subscription | accept (deferred) | per-app metered key is a Deferred Idea (256-CONTEXT); proxy covers operator-trusted apps only |
</threat_model>
