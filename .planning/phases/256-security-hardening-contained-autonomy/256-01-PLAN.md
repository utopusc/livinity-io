<objective>
WS-A — Contained Autonomy. Close LIVOS-002 (the agent's shell/files/docker tools auto-execute
on the host as `bruce` with `permissionMode:'dontAsk'` and a dead approval gate). Per the
operator-locked decision and SECURITY-REMEDIATION-DESIGN.md, KEEP autonomy and move the safety
boundary onto the OS/network: (1) bubblewrap-sandbox the `shell` tool exec, (2) path-allowlist the
`files` tool, (3) route agent egress through a deny-by-default allowlist proxy (breaks the
lethal-trifecta exfil leg), (4) scrub host secrets from the agent child environment, (5) git-snapshot
every agent run for one-revert undo. NO manual per-action approval gate is reintroduced.

Purpose: a fully prompt-injected agent can neither read `/opt/livos/.env` / the JWT secret, nor
phone home, nor leave a non-revertible change — while ordinary autonomous ops keep working.
Output: a `sandbox.ts` bwrap wrapper + scrubbed env, a `files-sandbox.ts` allowlist, an
`agent-git-snapshot.ts` reversibility layer, wired into `shell.ts` + `daemon.ts`, plus the
bubblewrap/proxy apt deps in both installer scripts.

WORKSPACE-ROOT INVARIANT (revision fix B): all three layers in this plan agree on ONE agent-workspace
root — `LIV_AGENT_WORKSPACE` (default `/opt/livos/data/agent-workspace`). The bwrap shell cwd +
write-root, the `files`-tool allowlist, and the git snapshot all bind/track that SAME path. The agent
must NOT be able to write into `/opt/liv` (its own compiled code/source tree); `/opt/liv` is never the
bwrap write-root and is never on the files allowlist.

SCOPE NOTE for the operator (confirm before execution): the stripped-context injection-proof
**classifier gate** for irreversible off-box ops (force-push, prod deploy/migration, mass-delete,
IAM grants) is INTENTIONALLY DEFERRED out of this plan. Rationale: the four OS/network layers in
this plan already close the trifecta (no exfil path → injection cannot achieve off-box harm), the
classifier is a net-new subsystem that would push this plan past the context budget, and it is an
"only retained gate" nicety, not a trifecta-leg. If the operator wants it in-phase, it becomes
256-05-PLAN (a dedicated TDD plan). Flagged in the source audit as "may be deferred to a sub-plan."
</objective>
