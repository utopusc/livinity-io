<objective>
WS-A layer 5 — the injection-proof classifier gate (the previously-deferred "only retained human gate"
from SECURITY-REMEDIATION-DESIGN.md, the Claude Code auto-mode model). 256-01 closed the trifecta with
four OS/network layers (bwrap sandbox, files allowlist, egress proxy, cred scrub) + a reversibility
snapshot. This plan adds the FIFTH defense-in-depth layer: a pre-execution gate that, for IRREVERSIBLE /
off-box operations ONLY, blocks and requires explicit operator approval. Everything else stays fully
autonomous — the `permissionMode:'dontAsk'` autonomy for ordinary ops is NOT regressed (SC7).

Per the design doc (lines 26, 32, 51): "the only retained human gate … a stripped-context classifier —
it sees the tool call but NOT tool output, so injected file/web content can't manipulate it — that blocks
just: force-push/push-to-main, prod deploy/migration, mass-delete of pre-session files, IAM/secret
grants, sending data off-box. Everything else stays fully autonomous."

Purpose: close LIVOS-002's defense-in-depth layer 5. Even with the trifecta broken, a prompt-injected
agent could still attempt an irreversible off-box action that the egress proxy alone does not cover
(e.g. `git push --force` to GitHub — GitHub IS on the egress allowlist, so the network layer permits it).
The classifier is the last gate that catches those specific irreversible ops, and ONLY those, while
leaving ordinary autonomous ops untouched.

Output: a pure, deterministic, output-blind `irreversible-classifier.ts` rule-set; a revived approval
hook wired into the SINGLE in-process tool-exec choke point (`toolRegistry.execute`); the dead
`ApprovalManager` (LIVOS-002 "unreachable subsystem") made reachable again — but ONLY for the
irreversible set.

INJECTION-PROOF INVARIANT (the whole point): the classifier's input is the TOOL CALL — the tool name
plus the command string / file path / params the agent emitted. It is NEVER given tool OUTPUT, file
contents, or web-fetch results. A prompt injected into a file the agent reads cannot reach the
classifier's decision surface. This is why the classifier sits at `execute()` BEFORE `tool.execute()`
runs and reads only `(name, params)` — never a prior result.

DETERMINISTIC-FIRST INVARIANT: the classifier is a rule-set (normalized-token + regex matching over the
command/args), so it is fully unit-testable with no live model. An LLM "second opinion" is explicitly
OPTIONAL and OFF the critical path — if wired at all, it can only ADD a block (fail-safe), never relax a
rule-set block, and a missing/slow model must default to the deterministic verdict (never fail-open).

CHAIN NOTE (parallel-safety): this plan shares `sdk-agent-runner.ts` with 256-01 Task 3 (the git-snapshot
wiring), so it is serialized behind 256-01 (wave 2, depends_on 256-01). It runs in parallel with 256-02
(also wave 2, depends_on 256-01) because 256-02 touches only livos/* + installer scripts — zero overlap.
</objective>

<classifier_policy>
The classifier returns `{ irreversible: boolean; category?: string; reason?: string }` from
`(toolName, params)` ONLY. IRREVERSIBLE categories (the ONLY things that block) — design doc line 51:

1. force-push / push-to-main: `shell`/`docker_exec` command matching
   `git push` with `--force`/`-f`/`--force-with-lease`, OR `git push` whose ref/branch is `main`/`master`
   (incl. `HEAD:main`), OR `git push` with no explicit non-protected branch to a remote.
2. prod deploy / migration: command matching a deploy verb to a prod target — `update.sh` on a remote,
   `docker compose ... up` against a prod compose, `prisma migrate deploy` / `… migrate reset` /
   `drop database` / `DROP TABLE` / `TRUNCATE`, `terraform apply`, `kubectl apply`/`delete` on a non-local
   context. (Rule-set covers the common verbs; the list is conservative — unmatched deploy verbs simply
   stay autonomous, the gate never over-blocks ordinary builds.)
3. mass-delete of pre-session files: `rm -rf` / `rm -r` / `find … -delete` / `git clean -fdx` whose target
   is OUTSIDE the per-session agent workspace (resolved against `LIV_AGENT_WORKSPACE` from sandbox.ts) OR a
   broad glob (`/`, `~`, `/opt`, `*` at a filesystem root). Deletes confined to the workspace are reversible
   (256-01 snapshot) → NOT blocked.
4. IAM / secret grants: `setfacl`, `chmod 777`/`+s` on a sensitive path, `usermod -aG`, `gh secret set`,
   `aws iam`, `gcloud projects add-iam-policy-binding`, writing to `~/.ssh/authorized_keys`,
   `git config … credential`, any command writing a secret to a shared/credential path.
5. send data off-box: `curl`/`wget`/`http` with an upload verb (`-X POST`/`-X PUT`/`--data`/`-d`/`-T`/
   `--upload-file`/`-F`) to a host that is NOT on the egress allowlist (reuse 256-01's allowlist set:
   api.anthropic.com, generativelanguage.googleapis.com, github.com, *.githubusercontent.com,
   registry.npmjs.org/com); also `scp`/`rsync … user@host:`/`nc`/`ncat` to a remote. A POST to an
   allowlisted host (e.g. the LLM API) is NOT blocked (normal agent traffic).

EVERYTHING ELSE → `irreversible:false` → FAST-ALLOW (no approval, full autonomy). The default is ALLOW;
only an affirmative rule match blocks. This is the operator-locked invariant: do NOT regress dontAsk
autonomy for ordinary ops (SC7). Normalize the command before matching (strip quoting, collapse
whitespace, lowercase the verb tokens) so trivially-obfuscated variants (`git   push  --force`) still match.
</classifier_policy>
