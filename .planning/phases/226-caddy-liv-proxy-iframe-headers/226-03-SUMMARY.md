## Rule 4 Findings (full architectural analysis in DEPLOY-LOG.md)

### Finding 1 — Installer regex too narrow (Rule 1 bug)

`scripts/install-liv-caddy-snippet.sh` Step 5 detection regex `^[[:space:]]*bruce\.livinity\.io[[:space:]]*\{` misses the live `http://bruce.livinity.io {` form. Installer would hit its hard-fail branch.

### Finding 2 — Caddyfile is dynamically generated by livinityd (Rule 4 architectural)

`livos/packages/livinityd/source/modules/domain/caddy.ts` writes `/etc/caddy/Caddyfile` from scratch on every regen (3 documented `reloadCaddy()` call sites). Any in-place edit by the installer would be wiped on next regen trigger (app install / share / subdomain change).

### Finding 3 — Plan 226-01's strategy is structurally incompatible with the livinityd model

The conf.d/ snippet drop is fine (livinityd never touches that directory), but the two `import` line edits to `/etc/caddy/Caddyfile` are not regen-survivable. The fix has to be in caddy.ts, not in an external installer.

## Options for Phase 226 Closure (operator selection required)

### Option A (RECOMMENDED): Patch caddy.ts to emit `/liv` handler inline

Add the `@liv path` + `handle @liv` + `uri strip_prefix` + `reverse_proxy 127.0.0.1:3020` + `header_down -X-Frame-Options` + `header_down -Content-Security-Policy` + `header Content-Security-Policy ...` block to the `bruce.livinity.io` site emitter in caddy.ts. Survives every regen. Drops the external installer dependency. Plan 226-01's snippet becomes reference documentation. Test coverage via existing `caddy.test.ts`.

**Scope:** Phase 226-04 — ~50 LOC change to caddy.ts + 1 test case + remove or no-op Step 4.7 in update.sh.

### Option B: Inline /liv handler in caddy.ts AND drop the snippet file

Variant of A — even simpler, kills the snippet file entirely.

### Option C: Hybrid — caddy.ts emits `import liv_assistant` (regen-survivable) + installer lays snippet under conf.d/

Adds 2 emit lines to caddy.ts (top-level `import conf.d/*.caddy` + in-block `import liv_assistant`). Keeps Plan 226-01's modularity. Installer still needed to lay the snippet file + create conf.d/.
