# Plan 104-12 — deploy-livinityd path-bug fix + liv-stack deploy

## Objective

Two coupled goals in one plan:

1. **Critical bug fix:** 104-11's `scripts/install/deploy-livinityd.sh` rsynced
   `livos/` → `/opt/livos/livos/` (NESTED), but livinityd's package.json
   declares `"@liv/core": "file:../../../liv/packages/core"`. That relative
   path resolves from `/opt/livos/packages/livinityd/` (three levels up =
   `/opt/liv/`). The nested layout pointed `../../../liv` at `/liv` (which
   does not exist) and broke `pnpm install` with `ENOENT: no such file or
   directory, scandir '/opt/livos/liv/packages/core'` on mainserver
   154.53.56.75 live test.

2. **Scope extension:** 104-11 documented liv-core/liv-worker/liv-memory
   systemd units as "deferred to Plan 104-12". This plan closes that
   boundary — the deploy now produces all 4 systemd services
   (livos.service + liv-core.service + liv-worker.service +
   liv-memory.service).

## Scope boundary (HARD)

- Targets the same single Ubuntu host that 104-11 targets. Multi-host is
  still OUT OF SCOPE.
- mcp-server is BUILT (so livinityd's on-demand spawn has a fresh
  `dist/index.js`) but NOT given a systemd unit — livinityd spawns it as a
  child process per P77's `additionalMcpServers` config.
- Mini PC `/opt/livos/` at deployed SHA stays untouched (D-104-NO-PROD-IMPACT).
- Sacred SHA `f3538e1d811992b782a9bb057d1b7f0a0189f95f` preserved.

## Tasks

### Task 1 — Fix path bugs in deploy-livinityd.sh + extend to liv stack

Edit `scripts/install/deploy-livinityd.sh`:

**Path fixes:**
- Retire `_DLD_LIVOS_SRC` (was `/opt/livos/livos/`). Everywhere it was used,
  substitute `_DLD_LIVOS_DIR` (`/opt/livos/`) — the flat layout matching
  Mini PC and Phase 65 rename memory.
- `schema.sql` path: `/opt/livos/livos/packages/...` → `/opt/livos/packages/...`
- systemd `WorkingDirectory`: `/opt/livos/livos` → `/opt/livos`
- rsync src `livos/` destination: `/opt/livos/livos/` → `/opt/livos/` (flat)
- BUILD-FAIL guard dist paths: `/opt/livos/packages/{config,ui}/dist`
- UI symlink target: `/opt/livos/packages/livinityd/ui`
- Pre-flight: assert `/opt/liv/packages/core/` exists before `pnpm install`
  (catches ENOENT failure mode loudly with a clear message)

**Liv-stack extensions:**
- `_dld_clone_source` extension: rsync `repo/liv/` → `/opt/liv/` (sibling)
- `_dld_build_liv_packages` (NEW): `npm install --omit=optional` in
  `/opt/liv`, then `npm run build` per package (core, worker, mcp-server,
  memory). Closes the update.sh memory-build gap per project memory.
- `_dld_sync_liv_dist_into_pnpm_store` (NEW): iterate ALL `@liv+<pkg>*`
  store dirs (not `head -1` — canonical Phase 31 BUILD-02 multi-dir pattern
  extended to all 4 liv packages).
- `_dld_write_liv_systemd_units` (NEW): writes `liv-core.service`,
  `liv-worker.service`, `liv-memory.service`. Each runs `node dist/index.js`
  with shared `EnvironmentFile=/opt/livos/.env`. Enable/start order:
  memory → worker → core.

**Public entry `deploy_livinityd` reordered:**
  1. system pkgs → postgres → redis
  2. clone (both livos + liv) → build livos (pnpm) → build liv (npm)
  3. sync liv dist into pnpm store
  4. jwt + .env
  5. liv systemd units → livos systemd unit (After=liv-core)
  6. health check + caddy reload
