# Plan 104-11 — install.sh full livinityd deployment

## Objective

Extend `scripts/install.sh` so that after the existing TLS/DNS/Caddy
bootstrap completes, install.sh proceeds to deploy the **full LivOS
application stack** (livinityd + UI + PostgreSQL + Redis + systemd unit)
on the same Ubuntu 24.04 host.

After this plan ships, the documented "single line install" UX
(`curl -fsSL ... | bash -s -- --mode hybrid --domain X --cf-token Y --cf-zone-id Z`)
on a fresh box results in the LivOS UI actually loading at `https://X` —
green padlock + LivOS login screen.

Trigger: live test on mainserver `154.53.56.75` proved 104-08 hybrid mode
ships green TLS + cert + green padlock, but the browser only sees a Caddy
placeholder response because livinityd was never installed.

## Scope boundary (HARD)

- Targets a SINGLE Ubuntu host (mainserver-style). Multi-host (DB on a
  separate server) is OUT OF SCOPE.
- Deploys `livinityd` only. `liv-core` / `liv-worker` / `liv-memory`
  systemd services are OUT OF SCOPE for v1; documented as Plan 104-12
  follow-up.
- D-104-NO-PROD-IMPACT: Mini PC at `/opt/livos/` already deployed via
  `update.sh` MUST remain untouched. install.sh's deploy step ONLY runs
  on fresh-install hosts or when explicitly re-run.

## Tasks

### Task 1 — `scripts/install/deploy-livinityd.sh` (NEW heavyweight helper)

Idempotent helper that installs system packages, configures Postgres +
Redis, clones source from GitHub, builds UI + config, writes
`/opt/livos/.env`, generates JWT secret, writes `livos.service` systemd
unit, starts it, health-checks port :8080, and updates Caddy to
`reverse_proxy 127.0.0.1:8080`.

**Sections (each section idempotent — `apt-get install` is no-op on
already-installed; `id livos`, `systemctl is-active`, `[ -d ... ]`
guards on every state mutation):**

1. **System packages** — Node.js 22 LTS via NodeSource setup script,
   `pnpm` via `npm i -g`, `postgresql` + `postgresql-client`,
   `redis-server`, `build-essential`, `python3`, `git`.

2. **PostgreSQL setup** — ensure `postgresql.service` running;
   conditionally create user `livos` with random password
   (`openssl rand -base64 24`); create DB `livos` owned by `livos`;
   apply `schema.sql` via `psql -d livos -f ...`. Skip create when user/db
   already exist.

3. **Redis setup** — ensure `redis-server.service` running; conditionally
   set `requirepass <random>` in `/etc/redis/redis.conf`; restart redis.
   Skip when password already configured.

4. **Source clone** — `git clone --depth 1` to `/tmp/livos-install-stage`
   (or `git pull` if exists); rsync to `/opt/livos/livos/`
   (excluding `.planning/`, `docker/`).

5. **Build** — `cd /opt/livos/livos && pnpm install --frozen-lockfile`;
   `pnpm --filter @livos/config build`; `pnpm --filter ui build`. Liv core
   etc. deferred to 104-12.

6. **`/opt/livos/.env`** — random passwords + JWT path + PORT/HOST/MODE/
   DOMAIN; mode 600. Re-runs reuse existing passwords (read+preserve).

7. **JWT secret** — `/opt/livos/data/secrets/jwt` mode 600 via
   `openssl rand -base64 32`. Reuse if exists.

8. **systemd unit `livos.service`** — `After=postgresql.service redis-server.service network.target`,
   `Requires=...`, `EnvironmentFile=/opt/livos/.env`, ExecStart points at
   `pnpm --filter livinityd start`, `Restart=on-failure`.

9. **Health check** — `curl -fsS http://127.0.0.1:8080/trpc/system.status`
   (or any 2xx route) with up to 30s retry budget. Fails loudly on
   timeout.

10. **Caddy update** — overwrite `/etc/caddy/Caddyfile` with the final
    `reverse_proxy 127.0.0.1:8080` shape appropriate for the active mode;
    `caddy reload`.

**Security:**
- All passwords randomly generated via `openssl rand -base64 24`.
- `/opt/livos/.env` mode 600.
- Postgres password flows via `PGPASSWORD` env (never on argv).
- No credentials in install.sh source.

## Threat model

- T-104-11-1: postgres password leak via process list → mitigate via
  `PGPASSWORD` env, never on argv.
- T-104-11-2: .env world-readable → mitigate via `chmod 600`.
- T-104-11-3: JWT secret leak → mitigate via `chmod 600` on
  `/opt/livos/data/secrets/jwt`.
- T-104-11-4: re-run rotates passwords + breaks existing data → mitigate
  via reuse-existing semantics; re-runs read existing `/opt/livos/.env`
  and preserve credentials.
