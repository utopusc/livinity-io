<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tRPC response → badge count | unreadCount rendered as integer in DOM |
| tRPC response → inbox body | Inbox content rendered via Streamdown (auto-escapes HTML) |
| filter input → client-side filter | No backend query; pure client filter on already-fetched data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-177-04-01 | Tampering (XSS) | unreadCount badge | mitigate | `Math.floor(Number(unreadCount))` integer cast — NaN coerces to 0 (badge hidden); non-integer floats are floored; string injection renders 0 |
| T-177-04-02 | Tampering (XSS) | inbox entry body | mitigate | Phase 175's `<Streamdown>` renders markdown with XSS escaping by default; raw HTML in inbox bodies cannot inject |
| T-177-04-03 | Information Disclosure | GlobalInboxWindow | accept | GlobalInboxWindow is admin-gated (same vault.inbox.listGlobal adminProcedure); client component only renders data already fetched through authenticated tRPC call |
| T-177-04-04 | Denial of Service | client-side filter | accept | Filter operates on already-fetched list in memory; no server round-trip; worst case is O(n) string match on a few hundred entries |
</threat_model>
