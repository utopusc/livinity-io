InboxEntryMeta shape (new type defined in inbox-reader.ts):
```typescript
export interface InboxEntryMeta {
  id: string            // "<agentId>/<runId>" — stable cross-router key
  agentId: string
  runId: string         // filename stem (without .md)
  runAt: string         // ISO from frontmatter
  triggeredBy: 'cron' | 'manual'
  durationMs: number
  status: 'success' | 'failed'
  read: boolean         // frontmatter `read:` field, default false if absent
  filePath: string      // absolute path — used internally by markRead/get
}
```

Walker pattern: `glob.sync('<vaultRoot>/items/*/inbox/*.md')` — but do NOT add glob dependency.
Use node:fs readdir with { withFileTypes: true } recursively:
1. readdir(`<vaultRoot>/items`, {withFileTypes:true}) → filter isDirectory → per-agent dirs
2. For each agent dir, check for `inbox/` subdir, readdir(`inbox/`) → filter `.md` files
3. Parse frontmatter from each file (same yaml parseFrontmatter helper as Phase 165)

Security guard in walker — validate that each resolved path starts with:
`path.resolve(vaultRoot, 'items') + path.sep`
Reject (skip silently) any entry that doesn't match this prefix.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tRPC caller → inbox file paths | filePath passed into markRead/get must stay inside vaultRoot/items/ |
| Walker → filesystem | readdir walks agentId subdirs; agentId could contain path traversal chars |
| agentId input | Used in path construction — must match ID_RE |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-177-03-01 | Information Disclosure | listGlobal (path traversal) | mitigate | `assertUnderItemsDir` validates every resolved path against `<vaultRoot>/items/` prefix before read; paths outside are silently skipped |
| T-177-03-02 | Tampering | markRead writes back to filesystem | mitigate | Only `read:` frontmatter field is rewritten; filePath validated with assertUnderItemsDir before any write |
| T-177-03-03 | Spoofing | agentId in listByAgent | mitigate | agentId validated with ID_RE `/^[0-9A-Za-z_-]{20,}$/` at tRPC input layer — rejects shell metachar injection |
| T-177-03-04 | Elevation of Privilege | vault.inbox.* procedures | mitigate | All 4 procedures use adminProcedure (same as vaultItemsRouter) — no unauthenticated access |
</threat_model>
