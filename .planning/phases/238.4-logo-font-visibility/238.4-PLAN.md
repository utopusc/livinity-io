# Phase 238.4 — Logo + font visibility (index.html sed inject + CSS overlay strengthen)

## Context

Operator 2026-05-27 evening after Phase 238.3 ship: "Logo değişmemiş bu arada Fontlar vs oralara gectin mi devam et" → logo hasn't changed, fonts haven't been addressed, continue.

### Discovery (single batched Mini PC SSH probe)

- **`livinity-overlay.css` is NOT loaded in the iframe HTML.** External `curl /liv/` HTML body grep for `livinity-overlay.css` → 0 matches. The Caddy `replace` directive Phase 232 designed for HTML injection isn't actually in the emitted Caddyfile (probe F shows `handle /liv/branding/*` block but NO replace directive on `@liv` handler). Phase 238.3 already established that Mini PC's Caddy v2.11.3 lacks the `http.handlers.replace_response` plugin.
- **The CSS file IS served**: `curl /liv/branding/livinity-overlay.css` → HTTP 200 (669 bytes content correct). Same for `favicon.svg` (240 bytes). Just nothing references them.
- **Browser favicon is AionUi default**: index.html line 12 `<link rel="icon" type="image/png" href="./pwa/icon-192.png" />` — the PNG ships in the AionUi tarball; never replaced.
- **theme-color is AionUi grey `#4E5969`** (line 11), not Livinity accent `#1d1d1f`.
- **Brand-icon is a 16px inline icon (kxt component)**, only rendered on `/team/...` routes — not the "logo" the operator means.
- **Brand-text already says "Liv AI"** (Phase 234-03 sed rebrand).
- AionUi UI lib is **Arco Design** — uses `--primary-1..10` RGB triplet CSS vars for theming. Overriding at `:root` cascades.

### Why operator sees no Livinity branding

Because `livinity-overlay.css` (which carries the Space Grotesk font + accent + Arco primary palette override) is **never loaded** in the iframe. The whole Phase 232 brand layer is dead.

## Fix scope

**IN scope (Phase 238.4)**:

1. **`caddy/branding/livinity-overlay.css` strengthened** (already-shipped Phase 232 file):
   - Adds Arco Design `--primary-1..10` RGB triplet overrides → entire palette collapses to Livinity mono-dark
   - More font-family selectors with `!important` (covers `.arco-btn`, `.arco-input`, `.arco-modal`, `.app-titlebar__brand-text`, etc.)
   - Explicit `.arco-btn-primary` background + border + hover styles
   - Headings with `letter-spacing: -0.01em` for wordmark polish

2. **`scripts/install-liv-assistant.sh` Step 238.4-E** — sed-edits `${CURRENT_LINK}/static/index.html` (4 substitutions, all idempotent via grep pre-check):
   1. Inject `<link rel="stylesheet" href="/liv/branding/livinity-overlay.css">` before `</head>` (replaces the missing Caddy `replace` directive)
   2. Favicon: `<link rel="icon" type="image/png" href="./pwa/icon-192.png" />` → `<link rel="icon" type="image/svg+xml" href="/liv/branding/favicon.svg" />`
   3. Apple-touch-icon: `<link rel="apple-touch-icon" href="./pwa/icon-180.png" />` → `<link rel="apple-touch-icon" href="/liv/branding/favicon.svg" />`
   4. theme-color: `#4E5969` → `#1d1d1f` (Livinity accent)

   All four sed substitutions skip when marker already present (idempotent on second+ run).

**OUT of scope**:
- Replacing `pwa/icon-{192,180,512}.png` files directly — covered by approach (b) the favicon link rewrite which redirects to our SVG (no need to generate PNGs)
- `brand/Liv.svg` and other inline brand SVGs in JS bundle — sed-rewriting JS-embedded SVGs would be complex; visible-text is already rebranded
- Inline brand-icon (kxt) on `/team/...` routes — generic 16px icon, not a logo per se
