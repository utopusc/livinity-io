## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UI client → livinityd tRPC | Authenticated React client requests display data + VNC ws URLs; input is untrusted |
| livinityd → x11vnc/VNC ws | The returned wsUrl is a capability that grants framebuffer + native input to an X display |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-254-01 | I (Information Disclosure) | displays.getVncUrl returning a ws URL for a display owned by another session | mitigate | getVncUrl calls displayManager.isOwner; if owner_session is non-empty and caller != owner → throw FORBIDDEN. Host `:1` (empty owner_session) is shared/readable. |
| T-254-02 | S (Spoofing) | userId/session taken from input | mitigate | userId resolved from ctx.currentUser?.id ONLY (never input); UNAUTHORIZED when absent (mirrors streams.start STRIDE-S rule). |
| T-254-03 | I | wsUrl capability token written to logs | mitigate | Log only the display id in displays.getVncUrl; never log wsUrl. |
| T-254-04 | E (Elevation) | unauthenticated client reaching displays.* | mitigate | Both routes use privateProcedure (auth-gated); getVncUrl additionally UNAUTHORIZED-guards on currentUser. |
| T-254-05 | D (DoS) | repeated getVncUrl spawning unbounded x11vnc | accept | StreamManager already enforces a per-user stream cap (StreamCapExceededError) — reused for free; no new control needed. |
</threat_model>
