    ```typescript
    // Exported alongside parseFrontmatter — Phase 179-01 extension.
    // Handles three frontmatter.tags shapes: undefined → [], string → [string], string[] → string[].
    // Any non-string array element is silently coerced via String() — no crash path.
    export function extractTags(frontmatter?: Record<string, unknown>): string[] {
      const raw = frontmatter?.tags
      if (raw === undefined || raw === null) return []
      if (typeof raw === 'string') return raw.length > 0 ? [raw] : []
      if (Array.isArray(raw)) return raw.map(String).filter(s => s.length > 0)
      return []
    }
    ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| YAML frontmatter → extractTags() | Untrusted content enters as already-CORE_SCHEMA-parsed Record; no code execution possible |
| relPath → deriveTopDir() | Path is already relative (walker guarantees); indexOf('/') cannot escape vault root |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-179-01-A | Tampering | deriveTopDir() | mitigate | Input is vaultRoot-relative, forward-slash normalized by walker — no `..` or absolute path possible at this stage |
| T-179-01-B | Info Disclosure | extractTags() returning raw frontmatter strings | accept | Tags are user-authored vault content, served only to authenticated clients; same threat level as existing label/path fields |
| T-179-01-C | DoS | Large tags array in frontmatter | accept | YAML CORE_SCHEMA has no array-size limit, but vault files are user's own content on their own server; no multi-tenant threat |
