Sidebar UI (Phase 174) reads `tree.json` for initial render then subscribes to `liv:tree:updated` for invalidation. Keeping resolution OUT of ItemStore preserves the store's single-responsibility (CRUD only).

    Implementation outline:
    - `buildTree(items)`: Build a `Map<string, Item>` by id. For each item, attach to parent's `children`. Items whose `parentId` is null → roots; items whose `parentId` is non-null but not present in the map → orphans (collected separately). Recursively assign `depth` starting at 0 for roots / orphans. Sort siblings by `(b.item.pinned ? 1 : 0) - (a.item.pinned ? 1 : 0)` (pinned-first) then `b.item.updatedAt - a.item.updatedAt` (newest first). Return `{roots, orphans}`.
    - `depthOf(items, itemId)`: walk `parentId` chain; return -1 if itemId not found; return 0 if its parentId is null; otherwise `1 + depthOf(items, parent.id)` (iterative, not recursive — bound by hard cap + epsilon to avoid stack overflow on corrupt data). Cycle-safe: maintain a `seen: Set<string>`; if you revisit an id, return `Number.POSITIVE_INFINITY` (caller treats infinity as "would exceed any cap" — defensive).
    - `validateMove(items, itemId, newParentId)`:
        1. If `itemId === newParentId` → `{ok: false, reason: 'self'}`
        2. If newParentId !== null AND no item exists with that id → `{ok: false, reason: 'not-found'}`
        3. If itemId not in items → `{ok: false, reason: 'not-found'}`
        4. Cycle check: if newParentId is itemId itself OR a descendant of itemId → `{ok: false, reason: 'cycle'}`. Implement by walking newParentId's parent chain upward; if you ever hit itemId, that's a cycle. (Also handle the "newParentId IS a descendant" case by walking the subtree of itemId downward — both directions matter for general graph correctness.)
        5. Archived-parent check: if the proposed new parent has `archivedAt !== null` → `{ok: false, reason: 'archived-parent'}`
        6. Compute the new depth: `depthOf(newParent) + 1 + maxDescendantDepthIncrement(itemId)`. The `maxDescendantDepthIncrement` is the deepest descendant chain rooted at itemId, computed as `0` for a leaf and `1 + max(children)` recursively. Implement iteratively with a stack to avoid recursion on deep trees.
        7. If newDepth >= DEPTH_HARD_CAP (8) → `{ok: false, reason: 'depth-exceeds-hard-cap'}`
        8. If newDepth >= DEPTH_SOFT_CAP (5) → `{ok: true, warn: 'depth-exceeds-soft-cap'}`
        9. Else → `{ok: true}`
    - `writeTreeCache(vaultRoot, items)`: mirror cc-pty/session-store.ts:117-127. Build via `buildTree(items)`, wrap in `{schemaVersion: TREE_SCHEMA_VERSION, generatedAt: Date.now(), roots, orphans}`, atomic-write to `<vaultRoot>/tree.json` via `.tmp` + `fs.rename`. `await fs.mkdir(vaultRoot, {recursive: true})` first for safety.
