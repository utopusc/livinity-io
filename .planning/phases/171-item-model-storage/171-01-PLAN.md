  id: string                  // UUID v7 (time-sortable; nanoid)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env (operator) → resolver | `LIV_VAULT_ROOT` env var crosses from systemd unit / shell into livinityd process — untrusted shape, must reject empty string and resolve absolute path only on consumer side (Plan 171-02 owns path-normalization) |
| nanoid PRNG → id space | Cryptographic-strength CSPRNG; Item ids enter filesystem paths in Plan 171-02 — alphabet must be filesystem-safe (nanoid v7 default alphabet `[0-9a-z_-]` is) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-171-01-01 | Tampering | LIV_VAULT_ROOT env | mitigate | Resolver returns string-only — empty/missing falls through to hard-coded fallback. Consumer (Plan 171-02) MUST `path.resolve()` + `path.normalize()` + reject relative paths before any filesystem op. |
| T-171-01-02 | Information Disclosure | newItemId | accept | UUID v7 leaks ~48 bits of timestamp by design (that IS the feature — D-V38-B time-sortability). No PII; ids are not security tokens. |
| T-171-01-03 | Spoofing | discriminator field | mitigate | `type: 'project' | 'agent' | 'chat'` is a literal-union at compile time. Plan 171-02 item-store re-validates `type` on every load (zod or hand-rolled) to reject tampered on-disk files. |
</threat_model>
