<objective>
Wire Phase 160-01's Haiku routing onto the **SDK subscription path** (`AgentSessionManager → @anthropic-ai/claude-agent-sdk → api.anthropic.com`) so that LivOS internal NativeApp / WebApp computer-use sessions actually hit `claude-haiku-4-5-20251001` instead of the user's chat model (`claude-sonnet-4-6`).

Phase 160-01 routed the **broker** path (api.livinity.io external clients — Bolt.diy, Cline). The LivOS UI goes through the SDK path which bypasses the broker entirely. Operator UAT (2026-05-19) showed every NativeApp Chat turn still hitting Sonnet. This plan closes that gap inside `consumeAndRelay()`.

Detection signal (per D-161-A): `session.conversationId?.startsWith('native:') || session.conversationId?.startsWith('webapp:')`. The UI hooks (`use-native-app-agent.ts`, `use-webapp-agent.ts`) already unconditionally emit this prefix — no UI changes needed in this plan.

Purpose: Bring LivOS internal computer-use loops onto the same Haiku contract that Phase 160-01 ships at the broker layer. ~5-10x cheaper + faster Haiku turns for screenshot-grounded coordinate extraction; chat reasoning quality preserved by routing only `native:` / `webapp:` sessions.

Output: 1 modified file (`agent-session.ts`) + 1 new test file (`agent-session.computer-use.test.ts`).
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-161-01-02 | Spoofing | A malicious WS client claims an admin user's conversationId | mitigate | userId derivation already gated by `is-authenticated.ts` middleware (JWT or X-Api-Key). conversationId prefix is informational, not auth. No new attack surface. |
