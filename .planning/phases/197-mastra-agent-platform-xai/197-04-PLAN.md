`ApprovalManager` (in-process, module-scope in mastra-router.ts):
```ts
class ApprovalManager {
  private pending = new Map<string, {resolve: (approved: boolean) => void, reject: (err: Error) => void, threadId: string, createdAt: number}>()

  /** Called from inside the agent stream when a requireApproval:true tool fires. Returns a Promise that the SSE handler awaits before emitting tool-result. */
  awaitApproval(toolCallId: string, threadId: string, timeoutMs = 300_000): Promise<boolean> {
    return new Promise((resolve, reject) => {
      this.pending.set(toolCallId, {resolve, reject, threadId, createdAt: Date.now()})
      setTimeout(() => {
        const entry = this.pending.get(toolCallId)
        if (entry) {
          this.pending.delete(toolCallId)
          entry.reject(new Error('approval-timeout'))
        }
      }, timeoutMs)
    })
  }

  /** Called from the mastra.agent.approve mutation handler. Returns true if a pending entry was resolved. */
  resolve(toolCallId: string, approved: boolean): boolean {
    const entry = this.pending.get(toolCallId)
    if (!entry) return false
    this.pending.delete(toolCallId)
    entry.resolve(approved)
    return true
  }

  /** Called when the agent stream is cancelled — reject all pending for that thread. Returns count rejected. */
  rejectByThread(threadId: string, reason: string): number {
    let n = 0
    for (const [id, entry] of this.pending) {
      if (entry.threadId === threadId) {
        this.pending.delete(id)
        entry.reject(new Error(reason))
        n++
      }
    }
    return n
  }
}
```

A SINGLE ApprovalManager instance is constructed inside createMastraRouter (or accepted via deps for test injection). It's NOT exported globally — the router factory closes over it and the mutation handlers use it via closure. This keeps approval state per-livinityd-process which is exactly what we want (memory cleared on restart; Plan 197-05 workflow resumption is a separate snapshot-based concern).

`AbortController` lifecycle:
- Created per-stream-call inside the SSE procedure body
- Stored in module-scope `Map<threadId, AbortController>` so cancel mutation can find it
- Wired to the SSE response's disconnect event so client close aborts the underlying Mastra run
- Stream procedure's finally block cleans up the Map entry + calls approvalManager.rejectByThread
