<objective>
Fix the resolution-order bug where `generateAppTemplate(appId)` (builtin) is tried FIRST (apps.ts:498) so any app present in builtin-apps.ts installs the BUILTIN def and never the catalog one — even when the catalog def is strictly better. Proven by n8n: builtin = bind mount + `n8nio/n8n:latest` (unpinned) + port 5678; catalog = named volume + pinned `2.26.4` + unique port 41292. The builtin shadows the catalog, so the worse def was installed.

The fix is precedence-aware: an explicit allowlist of SPECIAL builtins (AI-broker / docker.sock / privileged) always keeps builtin precedence; for every other (plain) builtin, prefer the catalog when the catalog actually has the app.

Purpose: deliver CONTEXT-locked decision #8 (catalog > builtin precedence) — installs use the well-engineered catalog defs.

Output: New `apps/builtin-precedence.ts` (allowlist + decision helper); `apps.ts install()` resolution chain reordered to consult it.
</objective>

 * Phase 286 (SC5) — catalog>builtin precedence.
 *
 * Resolution USED to try generateAppTemplate (builtin) first (apps.ts:498),

// SPECIAL builtins that ALWAYS keep builtin precedence (derived from the
