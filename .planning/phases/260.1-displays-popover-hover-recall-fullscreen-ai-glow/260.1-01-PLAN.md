SC-F backend: add a live AI/luse activity signal so the UI can pulse-glow a display the agent is
actively driving. Add a `last_input_at` ISO timestamp to the display registry, an additive
`updateLastInputAt(display)` write on the DisplayManager, expose `last_input_at` through `list()`
(and therefore the `displays.list` tRPC route the popover already polls), and stamp it from the luse /
computer-use INPUT handlers at the single `withScopedDisplay` chokepoint so every click / type / scroll /
paste / drag / move on a display refreshes its timestamp.

Purpose: drives SC-F's edge glow (UI computes `now - last_input_at < ~3s` → pulsing glow).
Output: `last_input_at` flowing end-to-end from input handler → Redis → displays.list payload.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| luse MCP child → displayManager (Redis) | The agent triggers input actions; each writes a timestamp into the display's Redis hash. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-260.1-01 | Tampering | updateLastInputAt write | accept | Writes only a timestamp to a display the handler already legitimately acted on (the same display withScopedDisplay scoped); no privilege change, no transport change. The display arg is already validated upstream by the input handlers. |
| T-260.1-02 | Denial of Service | fire-and-forget stamp | mitigate | Stamp is non-blocking + error-swallowed (`.catch(() => undefined)`) and guards on an empty Redis hash, so a torn-down display or Redis hiccup can never crash the agent or wedge an input action. |
| T-260.1-03 | Spoofing | cross-display stamp | accept | The stamped target is the SAME resolved display the action ran on (`displayArg ?? defaultDisplay`); a handler cannot stamp a display it did not act on. |
</threat_model>
