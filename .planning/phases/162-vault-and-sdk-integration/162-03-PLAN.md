<objective>
At livinityd boot, prove that the SDK subprocess can locate the Anthropic Max subscription credentials and complete a minimal `query()` round-trip. This validates the subscription-path env contract (`HOME=/root` per `reference_anthropic_subscription_state` / `BROKER_FORCE_ROOT_HOME`) WITHOUT waiting for a real user chat turn.

Why this matters:
- Phase 162-02 wires vault mode but until a real user chat lands, we have no signal that `query()` actually works on the deployed Mini PC. If auth is broken (credentials drift, env propagation regresses), the first user turn after Phase 162 ship would silently fail.
- The Settings UI (Phase 165) will surface this status to the operator (green / red badge: "Claude Code: ok" vs "auth failed: <reason>") so they don't have to dig through journal logs.
- This is the smallest non-invasive runtime probe we can run at boot.

Critical env contract (per `reference_anthropic_subscription_state`):
- The SDK subprocess MUST inherit `HOME=/root` so it reads `/root/.claude/.credentials.json` (the working OAuth file). The Mini PC has TWO `.credentials.json` files for the same Max account; only the /root copy works.
- `PATH` MUST be propagated so the spawned `claude` binary at `/usr/bin/claude` resolves.
- NO `ANTHROPIC_API_KEY` (BYOK is explicitly rejected per `feedback_subscription_only` — the broker uses subscription-path, not API key).
