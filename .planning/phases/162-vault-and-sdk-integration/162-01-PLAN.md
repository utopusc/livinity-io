<objective>
Bootstrap the Obsidian-compatible vault filesystem at `/home/bruce/livinity-vault/` per master plan decision D-V34-D. This is the foundation of the v34 LivOS↔Claude Code integration — every subsequent plan (162-02 sets cwd to this dir, 162-03 smoke-checks auth against it, 163+ writes surface-specific contexts) consumes the directory tree this plan materialises.

The scaffolder is a pure-Node async module that:
1. Detects whether `vaultPath` already exists (idempotency gate — never destroys user edits)
2. Materialises the full tree from bundled `vault-templates/` templates checked into the repo
3. `chown -R bruce:bruce` + applies mode `0755` for dirs, `0644` for files
4. Logs the result (`scaffolded`, `existing`, or `failed-non-fatal`) to the livinityd journal

Boot wire-up lives in `livos/packages/livinityd/source/index.ts` at the appropriate spot in `start()` — AFTER `this.ai.start()` (Redis is up so 162-03 can write status), BEFORE WS handler registration (so the vault exists when the first chat turn arrives).

Purpose: Without this directory + templates the SDK `cwd: '/home/bruce/livinity-vault'` + `settingSources: ['project']` options from 162-02 have nothing to load. CC would either error out or silently degrade to the legacy LivOS BASE_SYSTEM_PROMPT. This plan is the prerequisite that makes the v34 chat quality upgrade possible.

Output: 1 new module dir (`claude-runner/`) with index + scaffolder + test, 1 new templates dir tree under `source/data/vault-templates/`, 1 modified `index.ts` boot wire-up.

```typescript
// livos/packages/livinityd/source/modules/claude-runner/vault-scaffolder.ts
export interface ScaffoldVaultOptions {
  vaultPath: string;                           // e.g. '/home/bruce/livinity-vault'
  templatesDir?: string;                       // defaults to bundled vault-templates dir
  ownerUser?: string;                          // defaults to 'bruce'
  ownerGroup?: string;                         // defaults to 'bruce'
  logger?: { log: (msg: string) => void; error: (msg: string, err?: any) => void };
}

export type ScaffoldResult =
  | { status: 'scaffolded'; created: string[] }
  | { status: 'existing'; preserved: string[] }
  | { status: 'partial'; created: string[]; preserved: string[] }
  | { status: 'failed-non-fatal'; reason: string };

export async function scaffoldVault(opts: ScaffoldVaultOptions): Promise<ScaffoldResult>;
```

Key implementation rules:
1. **Resolve templatesDir** — when `opts.templatesDir` is undefined, resolve to `path.resolve(fileURLToPath(import.meta.url), '../../../data/vault-templates')`. This makes the module locate the bundled templates relative to its own file regardless of cwd. Use `import.meta.url` (tsx supports it).
