<objective>
This is the core wiring plan of Phase 162. Phase 162-01 created the vault filesystem. This plan upgrades `AgentSessionManager.consumeAndRelay()` so that when a vault config is supplied, the SDK `query()` call receives `cwd: vaultPath` + `settingSources: ['project']` + drops the custom `systemPrompt` (lets vault/CLAUDE.md drive). The Redis flag `liv:config:chat_backend` gates the behavior: `'vault'` (new default) → vault-mode ON, `'legacy'` → semantically Phase 161 behavior preserved for &lt;5s rollback.

**Architecture decision (init-once, read-many):** Redis flag reads happen ONCE at AiModule boot, NOT on every WS connection. AiModule exposes resolved values via `chatBackend` and `defaultChatModel` instance fields. The /ws/agent mount site reads from those fields synchronously and passes a resolved `vaultModeConfig` (or `undefined`) through to `createAgentWebSocketHandler` via factory opts. The factory STAYS synchronous (`export function ...`) so the existing `wss.on('connection', handler)` caller pattern continues to work without an async cascade.

Critical interaction with Phase 161: computer-use sessions (convId prefix `native:` / `webapp:`) ALWAYS force `claude-haiku-4-5-20251001` regardless of vault mode. The Phase 161 tier override runs FIRST; the vault mode contribution is a NEW additional override that applies ONLY when computer-use is false. The order is:

1. Tier defaults from agent config → `tier`
2. Phase 161 — if computerUse: `tier = 'haiku'`, model literal = `'claude-haiku-4-5-20251001'`
3. Phase 162 — if NOT computerUse AND vaultMode: model literal = `vaultModeConfig.defaultModel` (e.g. `'claude-opus-4-7'`)
4. Else: `tierToModel(tier)`

This preserves Phase 161's contract (testChatPathUntouchedRegression must still pass when vaultModeConfig is undefined) while introducing the vault-mode option as a strictly additive new branch.

Purpose: Without this wiring, the vault scaffold from 162-01 is dead weight — CC has no way to load `CLAUDE.md` / `.claude/skills/` / `.claude/commands/`. SDK options `cwd` + `settingSources: ['project']` are the documented mechanism per https://code.claude.com/docs/en/agent-sdk that triggers CC's project-context loading. Drop `systemPrompt` so vault/CLAUDE.md is the source of truth (LivOS BASE_SYSTEM_PROMPT was the inferior custom prompt that triggered the "worse Claude Code" feeling).

Output: 1 modified core source file (`agent-session.ts`), 1 new test file (`agent-session.vault-mode.test.ts`), 1 modified livinityd AI module (`ai/index.ts` adds two pre-resolved fields), 1 modified livinityd ws-agent factory (`ws-agent.ts` accepts vaultModeConfig via opts), 1 modified livinityd server mount (`server/index.ts` computes + passes vaultModeConfig).
