### Task 1 — `use-providers.ts` hook (native-fetch tRPC wrapper)

**Type:** auto

**File to create:** `livos/packages/liv-ai-app/src/lib/settings/use-providers.ts`

**Behavior:**
- Hook `useProviders()` returns `{providers: ProviderRow[], isLoading, error, refetch}`.
- `ProviderRow` shape: `{provider: 'xai'|'anthropic'|...; preview: string; addedAt: string}`.
- Fetches `/trpc/provider.config.list?batch=1&input=<encoded-null>` with credentials: 'include'.
- Reuses the `unwrapBatch` / `readBatchError` helpers (copy from `use-mcp-servers.ts`).
- Exposes `setProvider(provider, key)` → returns `{ok, restartTriggered, restartRequired, error?}`.
- Exposes `deleteProvider(provider)` → returns `{ok, restartTriggered, restartRequired, error?}`.
- Re-fetches list on window focus (same pattern as `use-mcp-servers.ts`).

**Done criteria:**
- File compiles via `pnpm --filter liv-ai-app build` (or `pnpm --filter liv-ai-app exec tsc --noEmit`).

### Task 2 — `ProvidersTab.tsx` (4th settings tab)

**Type:** auto

**File to create:** `livos/packages/liv-ai-app/components/settings/ProvidersTab.tsx`

**Behavior:**
- "use client" component.
- Three regions:
  1. **Configured providers (N)** — table-style list of `ProviderRow` items. Each row shows provider name + monospace preview + addedAt timestamp + a Delete button. Empty state: "No provider keys configured. Add one below to enable chat."
  2. **Add a provider** — `<select>` dropdown (xai / anthropic / openai / groq / mistral / ollama; only providers NOT already configured are selectable) + password input (`type="password"` so the browser never offers paste-back via autofill) + Save button.
  3. **Restart status banner** — surfaces under the Add form after Save. Three states:
     - `idle` (hidden)
     - `restarting` ("Saved. Restarting Liv AI gateway…" + spinner + 30s health-poll countdown).
     - `healthy` ("Gateway healthy.") for ~3s then hides.
     - `restart_required` ("Saved to Redis but gateway restart failed. SSH to Mini PC and run `sudo systemctl restart liv-claw-gateway`.") — sticky until next action.
- Plaintext-storage notice (D-204-02) rendered as a small `<p>` under the Add form: "Keys are stored as plaintext on this server. Same trust model as `/opt/livos/.env`."
- Health-poll loop: after `setProvider` succeeds AND `restartTriggered === true`, poll `GET /liv-ai-app/openclawos/health` (Caddy-proxied openclaw gateway health endpoint, returns `{"ok":true}` when healthy) every 1s for up-to-30s. First 200 → state `healthy`. After 30s with no 200 → state `restart_required`.
- INV-204-02: every visible string English.

**Done criteria:**
- Builds clean.
- Visual smoke (Plan 204-02 Task 5) on Mini PC.

### Task 4 — Sudoers drop-in + update.sh patch + fallback env-dir bootstrap

**Type:** auto

**Files to create:**
- `scripts/install/sudoers.d/livos-claw-gateway` (mode 0440 in repo too — file content; install step sets root:root on Mini PC).

**Files to modify:**
- `scripts/install/update.sh` (or wherever the existing Mini PC deploy script lives — confirm during task; if the canonical Mini PC `update.sh` is sourced from `/opt/livos/update.sh` directly without a repo-tracked copy, ship a new `scripts/install/204-provider-bootstrap.sh` that the operator runs once + document in 204-02-SUMMARY.md the operator step).

**Sudoers drop-in content:**
```
# Phase 204-02 — narrow grant so livinityd (running as bruce) can restart
# liv-claw-gateway when the operator saves an LLM provider key via the
# /settings → Providers tab. ONLY these two commands; nothing else.
bruce ALL=(root) NOPASSWD: /bin/systemctl restart liv-claw-gateway
bruce ALL=(root) NOPASSWD: /bin/systemctl status liv-claw-gateway
```

**Bootstrap script behavior (idempotent):**
- `install -m 0440 -o root -g root scripts/install/sudoers.d/livos-claw-gateway /etc/sudoers.d/livos-claw-gateway`
- `visudo -c -f /etc/sudoers.d/livos-claw-gateway` — exit non-zero on parse fail (rollback the install).
- `mkdir -p /opt/livos/etc && chown bruce:bruce /opt/livos/etc && chmod 0700 /opt/livos/etc` (D-204-05 fallback dir).
- Patch `/etc/systemd/system/liv-claw-gateway.service` if it doesn't already reference the fallback path: append `EnvironmentFile=-/opt/livos/etc/liv-claw-gateway.env` after the existing `EnvironmentFile=-/etc/default/liv-claw-gateway` line. If the file already contains the fallback line → no-op. After patch → `systemctl daemon-reload`.
- Idempotent re-runs: every step uses `install`/`mkdir -p`/`grep -q ... ||` guards.

**Done criteria:**
- Script runs clean on the Mini PC (Task 5).
- `sudo -n -u bruce sudo /bin/systemctl status liv-claw-gateway` (without password prompt) returns 0.
- `stat -c '%a %U' /opt/livos/etc` returns `700 bruce`.
