<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (curl) → Server5 install.sh route | unauthenticated public endpoint; ANY HTTP client can fetch the served bash script |
| Server5 → GitHub raw | outbound fetch to GitHub for the source-of-truth installer; subject to availability + content trust |
| Fallback path → GitHub clone | if upstream fails, clones full repo on the target VPS; subject to GitHub availability |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-111-01-01 | Tampering | upstream GitHub raw URL | accept | repo is public + access-controlled by maintainer; raw URL fetches the latest master commit — trade-off accepted because the alternative (pin to a SHA) would require manual rotation; mitigated downstream by HTTPS transport + GitHub's own signing |
| T-111-01-02 | Information Disclosure | served install.sh content | accept | installer is intentionally public (FOSS deploy script); no secrets baked in at this stage (api-key only baked into the one-liner the user copies, NOT into the served script) |
| T-111-01-03 | Denial of Service | GitHub rate-limit on raw fetch | mitigate | `revalidate: 300` (5-min Next.js fetch cache) + fallback git-clone bootstrap if upstream 4xx/5xx (already in route) |
| T-111-01-04 | Elevation of Privilege | curl-pipe-bash on target VPS | accept | this is the user's own VPS where they sudo'd; trust boundary is the user's existing root access, not our route; install.sh integrity guaranteed only by HTTPS to livinity.io (Caddy TLS) |
| T-111-01-05 | Repudiation | route patch deployment | mitigate | backup file `route.ts.pre-111-01.bak` allows instant rollback; SSH session logged on Server5 (auth.log) |

ASVS L1 mapping: this endpoint is unauthenticated by design (V1.4.1 documented exception — public install bootstrap). No PII flows through. No session establishment.
