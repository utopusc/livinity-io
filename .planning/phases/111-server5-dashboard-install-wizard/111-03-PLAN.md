<objective>
The wizard's **Hybrid mode** form asks the user for their Cloudflare API token. To make the install command copy-and-pasteable, the wizard must auto-resolve `cf-zone-id` from `domain + cf-token` (because the install.sh `--cf-zone-id` flag expects the zone UUID, not a human-readable name, and CF tokens are scoped per zone).

This plan ships ONE Next.js POST endpoint that:
1. Validates session cookie (D-111-EXISTING-AUTH)
2. Accepts `{domain, cfToken}` JSON body
3. Computes root domain (strip subdomain — e.g. `test.livinity.live` → `livinity.live`)
4. Calls `GET https://api.cloudflare.com/client/v4/zones?name=<root>` with `Authorization: Bearer <cfToken>`
5. Returns `{zone_id, root_domain, account_id}` on success
6. **NEVER persists the cf-token** (D-111-CF-TOKEN-NEVER-PERSISTED): no DB write, no Redis, no file write, no log line containing the token

Purpose: removes a tedious manual step (user copy-pasting zone ID from CF dashboard). Lets the wizard validate the token's scope (if zone not found → token is misscoped or wrong account).
Output: 1 new file on Server5 + local PLAN+SUMMARY.
</objective>

**Cloudflare API contract** (https://developers.cloudflare.com/api/operations/zones-get):
```
GET https://api.cloudflare.com/client/v4/zones?name=<root_domain>
Authorization: Bearer <user_token>

→ 200 { success: true, result: [{ id, name, account: { id, name }, status, ... }] }
→ 200 { success: true, result: [] }   // empty if token cannot see the zone
→ 403 { success: false, errors: [{ code: 9109, message: "Unauthorized..." }] }
```

**Session/auth pattern** (replicate from existing `/api/dashboard/route.ts`):
```typescript
import { getSession, SESSION_COOKIE_NAME } from "@/lib/auth";

async function getUser(req: NextRequest) {
  const token = req.cookies.get(SESSION_COOKIE_NAME)?.value;
  if (!token) return null;
  return getSession(token);
}
```

**Root-domain extraction** — naive PSL-free approach acceptable for v1:
- Split by `.` → take last 2 segments → join.
- Caveat: doesn't handle `.co.uk` style TLDs (e.g. `foo.co.uk` would resolve to `co.uk`). Acceptable for v1 since the bulk of CF customers use `.com`/`.io`/`.live`/`.dev`/`.app`. A future plan can add `psl` npm dep if needed.

import { NextRequest, NextResponse } from "next/server";
import { getSession, SESSION_COOKIE_NAME } from "@/lib/auth";

/**
 * Phase 111-03: resolve Cloudflare zone-id from (domain, cf-token).
 *
 * D-111-CF-TOKEN-NEVER-PERSISTED: the cf-token passes through this handler
 * in-memory only. NO database write, NO Redis SET, NO log line containing the
 * raw token. Token is used to call CF API once, then garbage-collected.
 *
 * D-111-EXISTING-AUTH: gated by liv_session cookie via @/lib/auth.getSession.
 */

async function getUser(req: NextRequest) {
  const token = req.cookies.get(SESSION_COOKIE_NAME)?.value;
  if (!token) return null;
  return getSession(token);
}

/** Strip subdomain — naive (no PSL). For test.livinity.live → livinity.live. */
function extractRootDomain(fqdn: string): string {
  const parts = fqdn.split(".").filter(Boolean);
  if (parts.length < 2) return fqdn;
  return parts.slice(-2).join(".");
}

export async function POST(req: NextRequest) {
  const user = await getUser(req);
  if (!user) return NextResponse.json({ error: "Unauthorized" }, { status: 401 });

  let body: { domain?: string; cfToken?: string };
  try { body = await req.json(); } catch { return NextResponse.json({ error: "Invalid JSON" }, { status: 400 }); }

  const domain = (body.domain ?? "").trim().toLowerCase();
  const cfToken = (body.cfToken ?? "").trim();

  if (!domain || !/^[a-z0-9.-]+\.[a-z]{2,}$/.test(domain)) {
    return NextResponse.json({ error: "Invalid domain" }, { status: 400 });
  }
  if (!cfToken || cfToken.length < 20) {
    return NextResponse.json({ error: "Invalid Cloudflare token" }, { status: 400 });
  }

  const root = extractRootDomain(domain);

  // Call CF API
  let cfRes: Response;
  try {
    cfRes = await fetch(
      `https://api.cloudflare.com/client/v4/zones?name=${encodeURIComponent(root)}`,
      {
        headers: {
          "Authorization": `Bearer ${cfToken}`,
          "Content-Type": "application/json",
        },
      },
    );
  } catch (e) {
    return NextResponse.json(
      { error: "Cloudflare API unreachable", details: String(e) },
      { status: 502 },
    );
  }

  type CfZonesResponse = {
    success: boolean;
    errors?: Array<{ code: number; message: string }>;
    result?: Array<{ id: string; name: string; account?: { id: string; name?: string }; status?: string }>;
  };

  let cfBody: CfZonesResponse;
  try { cfBody = (await cfRes.json()) as CfZonesResponse; } catch {
    return NextResponse.json({ error: "Cloudflare API returned non-JSON" }, { status: 502 });
  }

  if (!cfRes.ok || !cfBody.success) {
    const firstErr = cfBody.errors?.[0];
    const message = firstErr?.message ?? "Cloudflare API rejected the token";
    // 401/403 indicates the user-supplied token is invalid/insufficient — surface as 400 (client correctable)
    return NextResponse.json(
      { error: message, cf_status: cfRes.status, cf_code: firstErr?.code },
      { status: cfRes.status === 401 || cfRes.status === 403 ? 400 : 502 },
    );
  }

  if (!cfBody.result || cfBody.result.length === 0) {
    return NextResponse.json(
      { error: `Zone for ${root} not found — token may lack access or zone not registered in this Cloudflare account` },
      { status: 404 },
    );
  }

  const zone = cfBody.result[0];
  return NextResponse.json({
    zone_id: zone.id,
    root_domain: zone.name,
    account_id: zone.account?.id ?? null,
    status: zone.status ?? null,
  });
}

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/cf/resolve-zone | authenticated; carries CF token in POST body |
| Server5 → api.cloudflare.com | TLS to CF over public internet; auth via user-supplied Bearer token |
| pm2 logs ← handler errors | log output may transit local disk; risk of token-in-error |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-111-03-01 | Information Disclosure | cf-token leaking to logs | mitigate | handler NEVER `console.log`s the token or error objects containing it; error responses to CF use `firstErr.message` (CF strips token from its own error text); pm2 log audit step verifies absence |
| T-111-03-02 | Information Disclosure | cf-token persisted accidentally | mitigate | grep audit verifies no `pool.query`/`redis.set`/`fs.write` in handler; in-memory only |
| T-111-03-03 | Spoofing | endpoint hit without auth | mitigate | `getSession` cookie gate (401 on miss) |
| T-111-03-04 | Tampering | malformed domain causing CF API abuse | mitigate | regex `/^[a-z0-9.-]+\.[a-z]{2,}$/` rejects URLs, paths, ports before CF fetch |
| T-111-03-05 | DoS | unauthenticated CF API abuse via Server5 | mitigate | session-gated (T-111-03-03); legitimate user is rate-limited by their own session lifetime; downstream CF API enforces its own quotas |
| T-111-03-06 | Repudiation | token validation not audited | accept | resolve-zone is read-only on the user's own infra; no state mutation to audit |
| T-111-03-07 | Elevation of Privilege | token misused to mutate CF resources | accept | endpoint only does `GET /zones` (read-only); does NOT call DNS-edit endpoints; user-supplied token's permissions remain user-controlled |

ASVS L1 mapping: V4.1 (auth gate on session), V7.1 (input validation on domain), V9.1 (TLS to upstream).
</threat_model>
