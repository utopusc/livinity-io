<objective>
WS-C — Hard guardrails (the security spine, server-side). Build the ONE source of truth for "this app may NOT be
made public", reusing the exact signals the 257 WS-C sanitizer + the 256-04 daemon-bearer path already use, and
enforce it at the API (not just the UI). An app is PUBLIC-FORBIDDEN if ANY of: `manifest.neverPublic === true`;
it receives the 256-04 daemon bearer (its SubdomainConfig has an `upstreamBearer` / its compose carries a known
daemon-token var — readAppDaemonToken returns a value); its compose declares `/var/run/docker.sock`, `privileged`,
or `network_mode:host` (the compose-sanitizer signals); or `requiresLocalAiClis === true`.

Three deliverables:
1. `public-forbidden.ts` — a pure `isPublicForbidden(signals)` predicate + a typed reason, the single policy module
   both the API gate and the subdomain-wiring import.
2. `routes.ts` — a `setPublicAccess` tRPC mutation that (a) resolves the caller's owner-or-admin authority, (b)
   calls `isPublicForbidden` and rejects with a 403 TRPCError for a forbidden app, (c) persists the per-install
   PublicAccessInstallSetting, and (d) triggers a runtime Caddy regen (no reinstall).
3. `apps.ts` — persistence helpers (get/setPublicAccessSetting on the same Redis store as the SubdomainConfig) +
   wire `registerAppSubdomain` to resolve the persisted setting via `resolvePublicAccess` and thread it onto
   `SubdomainConfig.publicAccess` — re-asserting `isPublicForbidden` so a forbidden app NEVER gets a public config
   persisted/emitted even if a stale setting exists.

Purpose: make the never-public guarantee structural and server-enforced — the inverse of 256/257 cannot be undone
by a UI bug, a forged request, or a stale config. Default stays private (opt-in only).
Output: the policy module + test, the gated mutation, and the wired registerAppSubdomain + persistence.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tRPC caller → setPublicAccess mutation | a non-owner / non-admin could try to expose someone else's app |
| stale/forged persisted setting → registerAppSubdomain | a leftover public setting could try to expose a now-forbidden app |
| privileged app (docker.sock/bearer/host CLIs) → public toggle | exposing these would hand the daemon/host to the internet |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-258C-01 | EoP | a privileged/never-public app is exposed publicly | mitigate | isPublicForbidden (ONE source of truth, reusing 257/256 signals) rejects with FORBIDDEN at the mutation BEFORE persist/regen (Task 3 Test 1) AND registerAppSubdomain re-asserts so a forged setting can't slip through (Task 2 Test 3). |
| T-258C-02 | EoP / Spoofing | a non-owner member exposes another user's app | mitigate | owner-or-admin authority check (getUserAppInstance ownership + admin role) → FORBIDDEN for others (Task 3 Test 2). |
| T-258C-03 | Tampering | a stale Redis public setting outlives the app becoming forbidden (e.g. an update adds docker.sock) | mitigate | computeEffectivePublicAccess re-runs isPublicForbidden on EVERY registerAppSubdomain (every regen) → forbidden forces none regardless of the persisted setting (Task 2 Test 3, fail-closed). |
| T-258C-04 | Repudiation | who enabled public access | accept | enable is logged via the existing logger in registerAppSubdomain; a full audit trail is out of scope (CONTEXT deferred). |
</threat_model>
