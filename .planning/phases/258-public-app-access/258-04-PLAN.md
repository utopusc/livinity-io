<objective>
WS-D — UX (the Share dialog "Public access" section). Add a `PublicAccessSection` component to the app Share dialog
that surfaces the 258-03 server policy to the operator:
- LOCKED + disabled toggle with the forbidden reason for never-public/privileged apps (driven by
  `getPublicAccess`'s `forbidden`/`reason`).
- For a paths-capable app: pre-filled, editable manifest-suggested public path prefixes + an "enable paths" action.
- A `whole-app` toggle gated behind a confirmation dialog ("Anyone with the link can reach [app] without logging
  into LivOS. [App] has [its own / no detected] login. Continue?") using the manifest `hasOwnAuth` signal.
- After enabling, display the generated public URL. All changes apply at runtime via `setPublicAccess` (no
  reinstall).

Purpose: give the operator a safe, legible control surface for the inverse-of-hardening feature — the UI mirrors
(never overrides) the server-side guardrails: the toggle is locked for forbidden apps because the SERVER will 403
them anyway (258-03), and the whole-app confirm makes the "no fallback auth" risk explicit.
Output: the new section component + its mount in share-app-dialog.tsx.

REAL-CODE ANCHORS (read at plan time):
