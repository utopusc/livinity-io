<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app-author manifest → LivOS schema | an app declares publicAccess support — input that must be validated, not trusted as a toggle |
| operator per-install setting → resolved config | the operator's choice merges with the manifest into the effective config the emitter trusts |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-258A-01 | Elevation of Privilege | a manifest declaring publicAccess is NOT itself an enable — it's a capability declaration | mitigate | resolvePublicAccess defaults mode to 'none'; only the per-install operator setting (258-03, owner/admin-gated) activates public access. The manifest cannot self-enable. |
| T-258A-02 | Tampering | a malicious manifest injects a bare `/` catch-all path to shadow the gated block | mitigate | DEFAULT_CALCOM_PATHS documents catch-all-last; the 258-02 emitter (not WS-A) guarantees the gated handle stays last regardless of declared paths — WS-A normalizes/drops empty paths so a `''`/`/` cannot smuggle a universal prefix. |
| T-258A-03 | Spoofing | hasOwnAuth:true asserted by an app with no real login → operator exposes an unprotected admin surface | accept (UI-mitigated in 258-04) | hasOwnAuth is advisory; the 258-04 confirm dialog surfaces "the app has [its own / no detected] login" and 258-03 forbids the whole-app mode for any privileged-signal app regardless of hasOwnAuth. |
</threat_model>
