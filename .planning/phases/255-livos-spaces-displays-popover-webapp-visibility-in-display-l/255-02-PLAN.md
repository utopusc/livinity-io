<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → tRPC `displays.screenshot` | Authenticated user requests a screenshot of an arbitrary `:N`; untrusted `display` input crosses here |
| livinityd → maim/scrot subprocess | display id becomes part of subprocess env/argv |
| concurrent requests → shared process | multiple polls hit the same handler simultaneously |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-255-01 | Information disclosure | displays.screenshot leaking another user's display image | mitigate | Reuse `canAccessDisplay` verbatim (254-06): non-admin caller with `callerSession !== owner_session` gets FORBIDDEN before any capture. Owner derived from the Redis record's `owner_session`, caller from `ctx.currentUser` ONLY (never input). |
| T-255-02 | Spoofing | caller identity forged via input | mitigate | `userId = ctx.currentUser?.id`; UNAUTHORIZED if absent. Never read userId/role from `input`. |
| T-255-03 | Tampering | `display` arg injecting shell-meta into maim/scrot argv | mitigate | `displayIdSchema` regex `/^:\d+(\.\d+)?$/` rejects anything but `:N`/`:N.M` at the zod boundary; value passed as env var (not interpolated into a shell string), execFile (not exec). |
| T-255-04 | Information disclosure | `process.env.DISPLAY` race leaking user A's screen to user B's concurrent poll | mitigate | Task 1 threads DISPLAY into the subprocess `env` only — `process.env` is never globally mutated, so concurrent 2s polls cannot cross-contaminate (Pitfall 1). |
| T-255-05 | Information disclosure | capability-token / image-bytes leakage via logs | mitigate | Preserve 254 contract: log only `display=${input.display}`; never log dataUrl/base64; screenshot returns base64 (not a token). |
| T-255-06 | Denial of service | screenshot poll spam spawning unbounded maim processes | accept | Low risk: poll is gated `enabled:open` + 2s interval, capture has a 10s subprocess timeout, single-tenant operator box. Revisit only if multi-tenant load appears. |
</threat_model>
