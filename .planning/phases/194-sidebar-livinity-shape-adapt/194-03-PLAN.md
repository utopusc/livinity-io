<objective>
Change the Files app default landing path from `/Home` to the livinity-vault root, so opening the Files app from ANY launch surface (dock, mobile tab, Cmd+Space spotlight, desktop right-click menu) lands the operator inside the workspace the rest of LivOS is built around.

Purpose: today operators open Files and see the system root /Home — they then have to navigate two clicks deeper into livinity-vault to find their agent/project files. CONTEXT.md wants the Files app to OPEN INTO the vault directly. The checker flagged a missed chokepoint in `providers/apps.tsx` (`systemAppTo: '/files/Home'`) which is read by spotlight + desktop-content right-click — without updating it, those two launchers still drop into /Home.

Output: New `LIVINITY_VAULT_PATH` constant in features/files/constants.ts, `providers/apps.tsx` `systemAppTo` updated (the canonical chokepoint), dock.tsx + mobile-tab-bar.tsx updated to use it as the route for the Files app launch, spotlight + desktop-content updated (or confirmed they read from providers/apps.tsx already, in which case no edit needed), files-content.tsx fallback honors LIVINITY_VAULT_PATH.

**Adapter note:** Per the phase_dependency_warning, Phase 193 will rename `~bruce/livinity-vault/` → `~bruce/livinity/`. Plan 194-03 targets the CURRENT path. We introduce a single constant (`LIVINITY_VAULT_PATH = '/Home/livinity-vault'`) which Phase 193 can flip to `/Home/livinity` in a one-line follow-up. The Files app routes pass through to a backend `livinityd` directory listing — if the directory doesn't exist (e.g. fresh box), the existing ENOENT empty-state UI applies (per files-content.tsx + DirectoryListing). Verify this before shipping: probe `ls /home/bruce/livinity-vault/` (or whatever path the operator's Mini PC has today).

Operator's "remember last folder" preference: confirmed via `useFilesStore` exists; we do NOT touch it. The dock launch always uses the default; the in-window navigation state is preserved by `WindowRouterProvider` for the lifetime of the window. Per-user persistence across window-close is OUT OF SCOPE (deferred to v38.4 if asked).
