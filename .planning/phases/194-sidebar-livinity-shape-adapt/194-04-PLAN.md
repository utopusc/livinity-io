<objective>
When the operator clicks a project in the SidebarTree, spawn (or focus) a Project terminal tab in the TerminalTabStrip with `cwd = livinity-vault/projects/<slug>/`. Today, project clicks dead-end on a static ProjectDetail view (lines 225-228 of ai-chat/index.tsx); this plan replaces that with a working terminal tab consistent with how agent + chat tabs work.

Purpose: operator's "Project icerisinde Proje gelistirsin" intent (CONTEXT.md, referencing Phase 188 spec) — projects should be living workspaces, not detail pages. Aligns with Phase 190's terminal-tab paradigm.

Output: `TerminalTabType` union extended with `'project'`; `TerminalTabInfo` extended with optional `cwd?: string` field; `TerminalTab` icon mapping updated for project tabs; `handleItemSelect` project branch creates a tab and stores cwd directly on the tab; right-pane switch reads `activeTab.cwd` (no regex parse); 3 new vitest assertions.

**Adapter note:** Server-side cwd-on-attach is NOT in scope (would require WS handler changes per Phase 190's BareTerminal ws-handler inline-create code). For 194-04, after the BareTerminal mounts and receives `onAttached`, we send a `cd "<cwd>"\n` keystroke through the existing `sendStdin` WS message. This works against the current codebase and produces the right behavior (operator sees the cd in the terminal history; pwd is correct after).

The `<slug>` comes from `item.slug` populated by Plan 194-01's vault.items.list shape augmentation. ProjectDetail.tsx is NOT deleted (per `<deferred>` in CONTEXT.md, may be revived as a sidebar inline-detail in v38.4) — we just stop routing to it from the right pane, and remove the now-unused import line from ai-chat/index.tsx.

**Why we store cwd on the tab (not regex-parse the id):** The previous design had the right-pane switch do `id.match(/^liv-bare-proj-(.+)-[0-9a-f]{8}$/)` to extract the slug, then rebuild the cwd. That regex fails when the slug itself ends in `-<8hex>` (e.g. slug `proj-deadbeef` parses to `proj` instead of `proj-deadbeef`). The fix is to store cwd directly on the TerminalTabInfo at construction time — single source of truth, zero regex backtracking risk.
</objective>
