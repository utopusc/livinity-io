## Threat model

| Threat | Mitigation |
|---|---|
| Non-admin reaching `/admin/*` via cookie path | `requireAdmin()` re-reads `is_admin` from DB on every request; cookie is httpOnly+Secure. |
| API-key fallback opens new attack surface | Fallback ONLY accepts `liv_k_*` prefix + bcrypt-checked against `api_keys`, AND requires the resolved user to have `is_admin=true`. Same security model as the legacy x-api-key admin paths. |
| `users` PII leak via `/admin/users` | Endpoint is gated by `requireAdmin()` (T1 bridge). Only admin sessions reach it. RLS on `users` is unenforced today (CARRY-P212-RLS-POLICIES); when those policies land in P214 they will harden defense-in-depth. |
| Email exposure in /admin/users/[id] placeholder | Acceptable — admins are expected to see emails. |
