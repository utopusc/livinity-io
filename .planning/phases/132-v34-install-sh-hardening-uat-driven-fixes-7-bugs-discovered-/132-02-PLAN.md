<objective>
Fix Bug #3: `POST /api/account/api-keys` returns 403 for `emailVerified=false`,
but the Server5 platform has no email-delivery configured. New users register
→ wizard pops up → click Generate → 403 → stuck. This blocks every new-user
install.

The fix has two valid paths — pick one in 02-01:

**Path A (REMOVE the gate):** drop the `emailVerified` check from
`POST /api/account/api-keys`. Risk: spam signups can spam API key creation +
attempt to seed installs at livinity.io platform expense. Mitigate via rate
limiting (existing relay zone rate limits cover api.livinity.io but not
api-keys creation endpoint).

**Path B (MAKE email delivery work + auto-redirect to verify flow):** wire
SMTP (Resend / Mailgun / SES — operator picks), implement the
`/verify?token=X` route (already a route per Next.js build output, may be
stub), and route the wizard's 403 to a clear "check your email" toast with
a "Resend verification email" button. This is the proper fix but requires
operator to provision email infra.

**Recommended default**: **Path A + rate-limit** (ship today, unblocks customers
immediately; email-delivery is a v35+ scope item).
</objective>
