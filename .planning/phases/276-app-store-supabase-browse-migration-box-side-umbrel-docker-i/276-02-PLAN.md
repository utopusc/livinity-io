| Boundary | Description |
|----------|-------------|
| iframe (livinity.io/store) → box install bridge | postMessage carries appId → tRPC apps.install (untrusted appId) |
| box → Supabase /api/apps/<id> | install-by-id fetches compose (X-Api-Key gated) |
| box → external icon URL (img src) | installed-app tiles load a remote icon (rendered as <img>, never executed) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-276-04 | Tampering / SSRF | Removing AppRepository git-clone | accept (net WIN) | Deletes the SSRF-validated git-clone surface (Phase 257-02 / LIVOS-024). Removing the feature removes the attack surface. The remaining install path (Step 2) is the existing X-Api-Key-gated Supabase /api/apps/<id> endpoint — no new clone-of-arbitrary-URL vector. The SSRF gate test is deleted WITH the feature in plan 276-04 (expected). |
| T-276-05 | Spoofing | install-of-arbitrary-app via stubbed registry() | mitigate | registry() now returns `[]` — it can no longer surface attacker-supplied repo apps. Install still resolves ONLY via Step 1 (builtin allow-list) + Step 2 (Supabase catalog, X-Api-Key gated). Stubbing NARROWS the install surface; it does not open a new one. appId is still validated (`/^[a-zA-Z0-9-_]+$/`) and unresolved ids throw 'not found'. |
| T-276-06 | Info disclosure | livos:platform:api_key (Step 2 auth) | accept | KEEP — load-bearing for install-by-id + the iframe. This plan does not log, delete, or relocate it. Distinct from the account heartbeat key (do not conflate). |
| T-276-07 | Tampering | Remote icon URL in <img src> | accept | Icons render as `<img>` (no script execution); a malicious icon host can at worst serve a wrong image or 404 → onError placeholder. Replacement URLs are verified HTTP 200 + sourced from the operator-curated Supabase catalog / known upstream domains. No XSS/SSRF (browser img load, not server fetch). |

No new V5 input-validation or V6 crypto surface. registry-stub NARROWS attack surface. No HIGH introduced.
