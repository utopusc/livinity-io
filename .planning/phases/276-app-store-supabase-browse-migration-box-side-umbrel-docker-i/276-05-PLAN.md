<objective>
⚠️ **DEFERRED + GATED — DO NOT EXECUTE until two gates pass (see <gate> below).** Finish WS2 by removing the
Umbrel `tor` image end-to-end — BUT only after confirming the operator does not want the live "Remote Tor
Access" feature and that it is currently OFF on the box.

CORRECTED from the original (buggy) plan: the adversarial re-investigation proved two things the first
research/plan got wrong:
1. **`docker-compose.common.yml` is LOAD-BEARING and MUST NOT be deleted** — the live launcher `app-script`
   unconditionally merges `--file docker-compose.common.yml` into EVERY app `docker compose up` (app-script:356);
   it is the ONLY place apps attach to `livinity_main_network` (compose-generator emits no network). Deleting
   it breaks every app start/stop/install. KEEP it. (Original plan's deletion of it was a confirmed bug.)
2. **tor is NOT dead Umbrel cruft — it is a live, working feature.** The "Remote Tor Access" toggle
   (Settings → Advanced, advanced.tsx + setTorEnabled apps.ts:993) publishes real `.onion` hidden services
   when enabled. By DEFAULT it is OFF (torEnabled defaults false, apps.ts:165) and nothing uses the SOCKS
   proxy. So tor_proxy runs-but-unused by default — but removing it deletes a real feature, not just cruft.

This plan therefore does a COMPLETE, deliberate removal of the Tor remote-access feature (only if the
operator decides to drop it): the tor_proxy service, the tor image pull, the app-script REMOTE_TOR_ACCESS
branch, the tor sibling fragments, and the Remote Tor Access UI/plumbing — while PRESERVING the load-bearing
launcher (common.yml, the networks block, app-script's core, app-environment's NETWORK_IP).

Depends on plan 276-01 (which removed the `auth` service + auth-server pull). MUST run in a later wave.

Purpose: remove the (unused-by-default) Tor feature + its dead Umbrel image, without disturbing the live app
launcher/network. Output: networks-only compose; tor image/env/fragments/UI gone; common.yml + network kept.
</objective>
