Finish WS2: remove the dead Umbrel `tor` image end-to-end. Delete the `tor_proxy` service from the
legacy-compat compose (the `auth` service was already removed in plan 276-01), remove the now-dead tor
env from `app-environment.ts` (including `LIVINITY_TORRC`, which points at a torrc file being deleted),
and delete the sibling dead tor/auth fragments + the offline image tarballs + the orphan build/push scripts.

Per RESEARCH **Option (a)** (smallest blast radius on the boot path): keep the legacy-compat compose as
a NETWORKS-ONLY file so `appEnvironment 'up'` still creates `livinity_main_network` harmlessly (a compose
`up` with no services is a no-op + network create). Stopping the `appEnvironment 'up'` calls entirely
(Option b) is an explicit follow-up, NOT this phase.

`torEnabled`/`hiddenService` route+store plumbing (routes.ts:74/104/139/168/424/425, app.ts:88,
apps.ts setTorEnabled/getTorEnabled) — it is gated `false` and returns `''`/no-op (harmless). The
`setTorEnabled`/`getTorEnabled` integration test (apps.integration.test.ts:294-298) therefore stays
green and is NOT touched here.

Depends on plan 276-01 (which removed the `auth` service from the same docker-compose.yml). MUST run in a
later wave so the two edits to docker-compose.yml do not collide.

BOX-GATE (RESEARCH Pitfall 4 / MUST-CHECK #3): before removing the network, the operator must confirm via
`docker network inspect livinity_main_network` that no container is attached. Option (a) keeps the network
inline, so the risk is mitigated, but the box check is still required before the release that lands this.
