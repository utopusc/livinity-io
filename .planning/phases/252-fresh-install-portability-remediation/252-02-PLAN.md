<objective>
Make the persistent UI terminal portable. Today the PTY (1) does `sudo --user bruce --login bash`
with no sudoers grant (R8 — password prompt → spawn fails on a fresh box), and (2) pins the
username `'bruce'` in three layers with no runtime lookup (R4 — dead on any non-bruce desktop
user). Also (3) the `livos:v43:terminal_panel` flag defaults OFF and is never seeded (R10 — dock
entry hidden + WS 4403 until the operator sets it by hand).

LOCKED ordering (CONTEXT D-Wave2): do R8(b) FIRST — drop the self-`sudo` (livos.service already
runs as the desktop user), which also collapses R4's argv layer — THEN finish R4's Redis lookup
+ type widening + guard relaxation. R10 is an independent installer seed.

Purpose: a fresh install's terminal works for whatever desktop user the box was built with,
with no manual `redis-cli SET` and no sudoers editing.
Output: sudo-less direct `bash --login` spawn keyed on a runtime-resolved non-root user; a
terminal_panel flag seeded `true` at install time.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /livos/terminal/ws → PTY spawn | an authenticated proxy-token browser session can open a PTY; the spawned shell runs as a host OS user |
| Redis livos:desktop:user → spawn uid | the resolved username determines which OS user the shell runs as |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-252-04 | Elevation of Privilege | sudo-less bash spawn (R8) running as another user | mitigate | the spawn does NO `sudo`/`--user` — it inherits livos.service's own uid (the resolved non-root desktop user). It CANNOT switch to a different user, so dropping sudo removes (not adds) a privilege seam. The root-only guard (R4) blocks uid-0. |
| T-252-05 | Elevation of Privilege | PTY runs as root | mitigate | session.ts guard throws on `username==='root'||'0'` (D-243-NO-ROOT); the resolved value comes from `livos:desktop:user` which the installer sets to the non-root desktop user |
| T-252-06 | Tampering | attacker-controlled `livos:desktop:user` value | accept | Redis is loopback-bound + password-protected (REDIS_URL); writing this key already requires host-local Redis auth = equivalent to host compromise. The root guard still rejects `root`/`0` even if the key were tampered. |
| T-252-07 | Information Disclosure | terminal flag exposes a shell to any proxy-token holder | accept | the WS handler's Gate-1 proxy-token + Gate-2 flag are unchanged; R10 only flips a flag that the operator would otherwise set by hand — same exposure, no new path |
</threat_model>
