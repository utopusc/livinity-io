<objective>
Fix SC6: docked state must persist across a page refresh. The UI placement persistence ALREADY
EXISTS — Phase 131-02 built a Postgres pinnedWindows store and window-manager.tsx:307-330 hydrates
it on mount (re-opens each row as docked). And the streams survive because livinityd is
long-running + spawn is idempotent (re-mounting a recalled window re-attaches to the live stream,
not a fresh one).

The net-new SC6 work is RECONCILIATION: on hydrate, drop any pinned row whose underlying stream is
no longer live (e.g. after a livinityd restart cleared `activeNative`), so the operator never sees
a dead chip / a recall that spins forever. The single source of truth for "is this stream live" is
`displays.list` (which, after 260-02, now includes native displays).

Purpose: persist docked set across refresh AND self-heal dead pins on hydrate.
Output: reconcile in the hydration loop + a test.
</objective>
