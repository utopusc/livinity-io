<objective>
Fix SC2: native-app displays never appear in the top-right Displays/"Ekranlar" popover. There are
two separate display registries that never talk: native apps use `nativeDisplayAllocator` +
in-memory `activeNative` Map (native-routes.ts:218,245, range [10,100)) and write ZERO Redis
records; `displays.list` (computer-use/trpc-router.ts:76-87) only SCANs the Redis-backed
`displayManager`. So `dm.list()` never sees native displays.

Fix (Option A, preferred per RESEARCH): after a native spawn, call
`displayManager.registerExisting()` (display-manager.ts:316) — an idempotent, no-second-X-server,
no-allocator-advance adopt path built for the boot `:1` case. On native close, remove the record.
Once registered, the popover lists native displays automatically and screenshot/getVncUrl/the
DISPLAY_:N click-to-open window all work for free.

Purpose: surface native displays in the Displays popover (feeds SC5 badge + SC6 reconcile).
Output: native spawn registers into displayManager; close removes; unit test on merged displays.list.
</objective>
