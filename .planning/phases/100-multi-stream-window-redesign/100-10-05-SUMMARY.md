**Before:**
```
┌──────────────────────────────────────┐
│ [Gmail stream — 1280x720 at native]  │
│                                       │
│                                       │
├──────────────────────────────────────┤ ← stream bottom
```

**After:**
```
┌──────────────────────────────────────┐
│                                       │
│ [Gmail stream — object-cover         │
│  fills the entire window content     │
│  area, cropping if aspect mismatch]  │
│                                       │
│                                       │
└──────────────────────────────────────┘
```

Implementation: the noVNC container `<div>` (the one we own, before noVNC injects its own `<canvas>` child) gets the Tailwind class chain `[&_canvas]:h-full [&_canvas]:w-full [&_canvas]:object-cover`. The arbitrary descendant selector targets noVNC's injected canvas — we can't add classes to it directly because RFB.connect() creates the DOM node, but we can style descendants from the parent. `object-cover` crops/scales to fill the parent. If the aspect ratio mismatches (Chrome is 1280x720 = 16:9; the WebApp window might be portrait orientation), the crop is along the shorter axis — user said "tam sigsin" (fully fit) so cropping is acceptable per G-100-10-D default. Backend dynamic Chrome resize (xdotool windowsize on LivOS window resize) deferred to a follow-up plan if CSS-cover proves visually insufficient post-deploy.

## Deviations from Plan

Three minor deltas — all under Rule 1/3 auto-fix scope; none affecting the user-facing contract:

1. **[Rule 3 - Blocking issue] selectedSkillId lifted to drawer store.** The plan said to "thread `onReplaySkill` to the new floating button" but did not specify how to bridge the outside-window button's click back to the inside-window `SkillReplayScrubber` overlay (which is rendered by `WebAppStreamWindow`, a sibling component to `WebAppFloatingSkillsButton`). The clean solution: lift `selectedSkillId` from `WebAppStreamWindow`'s local `useState` into the drawer store as `selectedSkillIdByWebappId: Record<string, string | null>` + `setSelectedSkillId` setter. The floating button writes via `setSelectedSkillId(webappId, skillId)`; `WebAppStreamWindow` subscribes via `useWebAppDrawerStore((s) => s.selectedSkillIdByWebappId[webappId] ?? null)` and renders the scrubber.
