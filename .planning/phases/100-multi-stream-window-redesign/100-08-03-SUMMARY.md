## Architectural rationale

The descriptor branch closes the last gap from 100-08-02's input-routing analysis. **Native bytebot input.ts (computer-use/native/input.ts) does NOT use WEBAPPS_X11_ENV** — it spawns `xdotool` / `xclip` / `maim` with default `process.env`. The 100-08-02 cutover (WEBAPPS_X11_ENV → `:1`) covers Chrome / x11vnc / window-discovery / input-dispatcher but leaves native bytebot primitives untouched.

By setting `DISPLAY=:1` in the **per-WebApp MCP child's env at boot**, every native primitive call inside that child inherits `:1` automatically through `process.env`. No deeper edits needed in `native/input.ts` — child process inheritance is the single-point-of-truth.

The host bytebot variant (descriptor undefined) is byte-identical to the pre-100-08-03 behavior: `DISPLAY` defaults to `process.env.DISPLAY ?? ':0'`, XAUTHORITY uses the GDM-managed path. This preserves D-100-08-A's "bruce's `:0` desktop stays usable" promise — desktop-stream native app continues to drive bytebot on `:0` exactly as before.
