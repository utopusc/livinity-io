# Phase 100 Plan 09-08: Action Bar 2-Mode Chat Input Summary

**One-liner:** Replaces the persistent inline `WebAppChatBottomBar` shipped in 09-05 with a 2-mode state machine on the floating action bar (rendered OUTSIDE the WebApp window per 100-06). Default mode `'icons'` renders the existing 4-button row (Chat / Teach / Auto); clicking the Chat icon flips the same area to mode `'chat-input'` (text input + Send + Close X). Send / Enter / Escape / Close (X) all return to `'icons'`. Sacred SHA `f3538e1d811992b782a9bb057d1b7f0a0189f95f` preserved across both commits.

## What user reported

Verbatim feedback after the 09-05 deploy:

> "Message Liv... kismi pencerenin icinde olmamasi lazimdi assagida message iconuna tikladigimda o kisimin butun olarak inputa donusmesi lazimdi"

Translation: "The 'Message Liv…' area shouldn't be INSIDE the window. When I click the message icon at the bottom, that AREA should transform entirely into an input."

## What 09-05 shipped wrong

09-05 introduced `WebAppChatBottomBar` — a persistent slim text input + collapsible message log anchored at the bottom of every WebApp stream window via `absolute inset-x-0 bottom-0 z-10`. It was always visible; the Chat icon in the floating action bar (100-06) toggled its log expanded/collapsed via `toggleChatLog`.

The user's original Turkish quote in 09-CONTEXT.md ("Chat penceresi olmasin sadece yazi yazalim mesela. Yazilar sadece Alt kisimda gozuksun Butonlar kalsin o sirada.") was interpreted as "drop the drawer, show a persistent input at the bottom of the WebApp window." After the 09-05 deploy the user clarified that "Butonlar kalsin" referred to the icon bar staying as the DEFAULT view, and that the chat input shouldn't live inside the WebApp window at all — the icon-bar AREA itself should TRANSFORM into the input on Chat icon click, then transform back on Send / Close.

## What 09-08 ships

**A 2-mode state machine on the floating action bar.** Same area, two states, keyed on a per-webappId slot in the existing Zustand drawer store:

```
mode='icons' (default):       mode='chat-input' (Chat icon click):
┌──────┐ ┌──────┐ ┌──────┐    ┌─────────────────────────────┐
│ Chat │ │Teach │ │ Auto │    │  [Mesaj yaz...]  [Send] [X] │
└──────┘ └──────┘ └──────┘    └─────────────────────────────┘
```

- **Click Chat icon** → `setChatInputMode(webappId, 'chat-input')` → same `motion.div` re-renders with `<ChatInputBar/>`. Auto-focus on mount.
- **Type + press Enter** → `sendMessage(text)` via `useWebAppAgent` → clear input → `setChatInputMode(webappId, 'icons')`. Back to icon bar.
- **Click Send button** → same as Enter.
- **Press Escape (window-level keydown listener)** → return to `'icons'` WITHOUT sending.
- **Click X (Close)** → return to `'icons'` WITHOUT sending.
- **No input value / streaming in flight** → Send button disabled (visual `bg-neutral-100 cursor-not-allowed`); Enter is a no-op.

The persistent inline `WebAppChatBottomBar` JSX render call is REMOVED from `webapp-stream-window.tsx`. The component file is preserved with a `DEPRECATED 2026-05-10 (P100-09-08)` banner for revert safety; v34 cleanup may delete it outright.

## Deviations from Plan

Three minor deltas — all in the test-infrastructure layer, none affecting production code shape:

1. **[Rule 3 - Blocking issue] Test pattern adapted to file precedent.** The plan's Task 1 `<action>` block requested behavioral tests using `@testing-library/react` (mocking `useWebAppAgent`, simulating clicks, asserting store updates). React Testing Library is NOT installed in `livos/packages/ui` (D-NO-NEW-DEPS — same precedent as 95-04 / 95-06 / 67-04 / 09-05 / 09-06). The existing 21 + 5 (09-05) + 5 (09-06) invariants in `webapp-stream-window.unit.test.tsx` all use source-text regex over `readFileSync()` — the established pattern. Followed precedent: the 5 new T-09-08-NN invariants are source-text-based. The contract is still locked end-to-end (drawer-store fields + setter call shape + Chat-icon wire + Send/Close/Escape exit wires + sentinel grep on stream-window + deprecation banner), just via grep over the source rather than rendered DOM.

2. **[Rule 1 - Bug] Plan's `<interfaces>` ChatInputBar used `<Input>` from shadcn-components; actual implementation uses plain `<input>`.** The plan sketch imported `Input` from `@/shadcn-components/ui/input` plus `Button` from `@/shadcn-components/ui/button`. The shadcn `Input` is fine, but the floating bar lives inside a `Magnetic` + `motion.div` pill with very tight padding — using a plain `<input>` lets the styling stay flush with the pill background (`bg-transparent`, no nested border). Send + Close are plain `<button>` elements with `lucide-react` icons (`Send`, `X`), matching the existing icon-bar pattern in the same file (no shadcn `Button` import elsewhere in the file). Functionally identical to the plan's spec; visually tighter.

3. **[Rule 3 - Blocking issue] Two 09-05 invariants retired as superseded.** T-09-05-01 asserted `webapp-stream-window.tsx` renders `<WebAppChatBottomBar/>` — directly invalidated by 09-08's removal. T-09-05-04 asserted the Chat icon calls `toggleChatLog(webappId)` — directly invalidated by 09-08's rewire to `setChatInputMode(webappId, 'chat-input')`. Both retired with explanatory comments pointing at their replacements (T-09-08-04 and T-09-08-02 respectively). T-09-05-02 (Sheet host excludes 'chat' branch), T-09-05-03 (store retains 09-05 slots for back-compat), and T-09-05-05 (bottom-bar component file preserved) remain valid and still pass.
