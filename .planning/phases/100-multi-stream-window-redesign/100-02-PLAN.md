Apply the backend fix for the multi-stream root cause that 100-01 verified. Default path (per CONTEXT G-100-B B1, locked unless 100-01 says otherwise): swap the Chrome spawn argv from the two-element `'--new-window', opts.url` to the single-element `` `--app=${opts.url}` ``. The streaming layer (Phase 99-03 `VNC_PORT_COUNTER`) already supports multi-stream — the bug is upstream in Chrome spawn behavior.

Output: 1-line argv change in window-manager.ts, +1 new test (Test 11) in window-manager.test.ts, +100-02-SUMMARY.md.
