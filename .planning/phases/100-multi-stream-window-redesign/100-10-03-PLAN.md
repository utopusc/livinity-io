# Plan 100-10-03: Luse window-aware tools (list_windows + screenshot_window + focus_window)

<objective>
Implement the window-aware portion of D-100-10-C: three new MCP tools registered under the `mcp__luse__` namespace (post-rename from 100-10-02). They give the agent first-class window enumeration, per-window screenshot capture, and explicit focus-by-wid — all scoped to the caller's per-WebApp display (`LUSE_DISPLAY` env, set by 100-10-01's `WebAppWindowManager`). The agent gains the ability to "see what windows exist on my display, screenshot any of them, and switch focus" — exactly the capability the user requested ("istedigi pencerenin ss ini alabilsin... pencereler arasinda gezebilsin"). The click/type/scroll wrappers under the `mcp__luse__` namespace are NOT in this plan — they already exist as part of the post-rename `LUSE_TOOLS` array (renamed in 100-10-02 from the old `BYTEBOT_TOOLS`); only the three NEW window-aware tools land here.
</objective>

<must_haves>
- Three new entries in the `LUSE_TOOLS` array (post-100-10-02 rename): `list_windows`, `screenshot_window`, `focus_window` — each with valid Zod input schema + description.
- Three new handlers in `mcp/tools.ts` registered under names `mcp__luse__list_windows`, `mcp__luse__screenshot_window`, `mcp__luse__focus_window`.
- `list_windows` defaults to the caller's `LUSE_DISPLAY` env (per-WebApp display from 100-10-01) when no `display` arg is passed; returns an array of `{wid, title, geometry: {x, y, w, h}, display}`.
- `screenshot_window` accepts EITHER `{wid: number}` (window-bound capture) OR `{display: string}` (whole-display capture); returns `{b64, format: 'png', w, h}`.
- `focus_window` accepts `{wid: number}` and runs `xdotool windowactivate --sync <wid>`; returns `{ok: true}` on success.
- All three tools call existing `native/window.ts` helpers (`listWindows`, `screenshot`, etc.) — extend the native helpers if their current shape doesn't accept a display arg.
- Sacred SHA `f3538e1d811992b782a9bb057d1b7f0a0189f95f` preserved across all commits.
</must_haves>

**Step 3 — Add 3 handlers in `mcp/tools.ts`.** In `registerLuseTools()` (post-100-10-02 rename), append to the handler-map:

```typescript
'mcp__luse__list_windows': async (args: {display?: string}) => {
  const display = args.display ?? options.defaultDisplay ?? process.env.LUSE_DISPLAY
  const windows = await listWindows({display})
  return {
    content: [{type: 'text', text: JSON.stringify(windows)}],
    isError: false,
  }
},
'mcp__luse__screenshot_window': async (args: {wid?: number; display?: string}) => {
  if (args.wid !== undefined) {
    const shot = await captureScreenshot({wid: args.wid})
    return {
      content: [{type: 'image', data: shot.b64, mimeType: 'image/png'}],
      isError: false,
    }
  }
  if (args.display) {
    const shot = await captureScreenshot({display: args.display})
    return {
      content: [{type: 'image', data: shot.b64, mimeType: 'image/png'}],
      isError: false,
    }
  }
  return {
    content: [{type: 'text', text: 'Error: must provide wid or display'}],
    isError: true,
  }
},
'mcp__luse__focus_window': async (args: {wid: number}) => {
  // xdotool windowactivate --sync <wid_hex>
  const widHex = '0x' + args.wid.toString(16)
  const display = options.defaultDisplay ?? process.env.LUSE_DISPLAY ?? ':0'
  await spawn('xdotool', ['windowactivate', '--sync', widHex], {
    env: {...process.env, DISPLAY: display},
  })
  return {
    content: [{type: 'text', text: JSON.stringify({ok: true, wid: args.wid})}],
    isError: false,
  }
},
```
