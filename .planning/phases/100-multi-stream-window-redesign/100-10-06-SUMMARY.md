# Phase 100 Plan 10-06: Chat In-Place Response (Action Bar 3-Mode + Stop) Summary

**One-liner:** Extends the 09-08 2-mode floating action bar state machine (`'icons' | 'chat-input'`) to 3-mode by adding `'chat-response'` (D-100-10-E / Issue 6). After Send/Enter from the chat-input bar, the input area is REPLACED IN-PLACE by a streaming response panel showing the latest assistant message with a Stop button (Square icon, red bg) while `agent.isStreaming` is true. After streaming completes, the Stop button transitions to a "New message" (Plus icon, primary bg) that flips back to `'chat-input'` with response cleared. Close (X) always returns to `'icons'`. Escape from `'chat-response'` also returns to `'icons'`. Adds `useWebAppAgent.stopStreaming` — a thin alias for the existing `useAgentSocket.interrupt` (sends `{type: 'interrupt'}` over the WS — real runtime cancel, NOT a no-op). Sacred SHA `f3538e1d811992b782a9bb057d1b7f0a0189f95f` preserved across both commits.

## What user reported (Issue 6 / D-100-10-E from 100-10-CONTEXT.md)

The 09-08 plan shipped a 2-mode action bar where:
1. Click Chat icon → `'chat-input'` (input + Send + Close).
2. Type + Enter → `sendMessage(text)` AND immediately return to `'icons'` mode.

User feedback (Issue 6): the response should appear IN PLACE OF the input area — not flash through and end up somewhere else (the response was rendered far away, in the deprecated chat drawer or not at all visually). The user wants the SAME area to transform a third time:

- Step 1: icons row.
- Step 2: chat input (after Chat icon click).
- Step 3: chat response (after Send/Enter — REPLACES the input with the streaming reply).

## What 10-06 ships

### Three-mode state machine

```
mode='icons' (default):              mode='chat-input' (Chat icon click):
┌──────┐ ┌──────┐                    ┌─────────────────────────────┐
│ Chat │ │Teach │                    │  [Mesaj yaz...]  [Send] [X] │
└──────┘ └──────┘                    └─────────────────────────────┘
                                              │
                                              │ Send/Enter
                                              ▼
                                     mode='chat-response':
                                     ┌─────────────────────────────────────┐
                                     │ Hello! I can help with that...│   │
                                     │ [streaming caret blinks while │ ■ │ ← Stop (red, while streaming)
                                     │  isStreaming === true]        │ X │ ← Close (back to icons)
                                     └─────────────────────────────────────┘
                                              │
                                              │ stream completes
                                              ▼
                                     ┌─────────────────────────────────────┐
                                     │ Hello! I can help with that.  │ + │ ← New message (back to chat-input)
                                     │                               │ X │ ← Close (back to icons)
                                     └─────────────────────────────────────┘
```

- **Click Chat icon** (in IconBar) → `setChatInputMode(webappId, 'chat-input')` → ChatInputBar renders.
- **Type + Enter / click Send** (in ChatInputBar) → `agent.sendMessage(text)` → `onSent()` callback → parent flips to `'chat-response'`.
- **While `agent.isStreaming`** (in ChatResponseBar) → right-side button is a Square (Stop) icon with `bg-red-500 hover:bg-red-600`. Clicking calls `agent.stopStreaming()` which forwards to `agent.interrupt` which calls `ws.send({type: 'interrupt'})` — a REAL runtime cancel (NOT a no-op).
- **After streaming completes** → right-side button transitions to a Plus (New message) icon with `bg-primary`. Clicking flips back to `'chat-input'` so the user can type a follow-up.
- **Close (X) button** in `'chat-response'` → return to `'icons'` (response cleared on next entry).
- **Escape key** in `'chat-response'` → same as Close → return to `'icons'`.

### stopStreaming alias chain (W2 fix verification)

The W2 fix's concern was that `stopStreaming` must NOT be a no-op stub. Resolved chain:

```
useWebAppAgent.stopStreaming  (use-webapp-agent.ts L203-208)
    → agent.interrupt          (returned from useAgentSocket via destructure L82)
    → useAgentSocket.interrupt (use-agent-socket.ts L551-558)
        ws.send(JSON.stringify({type: 'interrupt'}))   ← REAL runtime cancel
        dispatch({type: 'FINALIZE_MESSAGE'})
        setIsStreaming(false)
        setAgentStatus({phase: 'idle', currentTool: null})
```

`grep -nE "abort|unsubscribe|cancel" livos/packages/ui/src/hooks/use-agent-socket.ts` returns **3** matches (lines 560, 563, 595 — the parallel `cancel` action that sends `{type: 'cancel'}` and the `cancel` property in the return statement). The `interrupt` action at L551-558 is the one our chain calls; both `interrupt` and `cancel` send WS messages, both are real runtime cancels.

## Deviations from Plan

Two minor deltas — both refinements, no architectural changes:

1. **[Rule 1 - Bug] ChatResponseBar uses `items-start` not `items-center` for proper text wrap layout.** The plan's interfaces sketch had `flex items-center gap-2 rounded-2xl ...` on the wrapper div. After implementing, realized that when the response is multi-line (likely common for AI replies), `items-center` would vertically center the right-side buttons relative to the text block — visually awkward. Switched to `flex items-start` so the Stop/New + Close buttons anchor at the top of the response. Added a `shrink-0` class to each button so they don't squish when text is long. Functional contract unchanged.

2. **[Rule 1 - Bug] ChatResponseBar uses `min-h-[20px]` on the text container so the bar doesn't collapse to zero height when `lastAssistant?.content` is empty (initial render, before the first token arrives).** The plan's sketch had `<div className='flex-1 text-caption-sm ...'>` with no min-height. Without a min-height, the first render of the response bar (immediately after Send/Enter, before any tokens stream back) would show as a zero-height empty div with just the caret + buttons — visually broken. Added `min-h-[20px]` (matches the caret's 14px height + a bit of breathing room). Functional contract unchanged.
