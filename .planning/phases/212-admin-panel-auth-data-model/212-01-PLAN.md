### T2 — Admin auth helper + Next.js middleware

**Files:**
- NEW `platform/web/src/lib/auth-admin.ts` — `getSessionUser(req): Promise<SessionUserWithAdmin|null>`, `requireAdmin(req): Promise<AdminContext|NextResponse>` (returns 401/403 NextResponse on failure, `{userId, username, email, isAdmin: true}` on success).
- NEW `platform/web/middleware.ts` — Next.js middleware gating `/admin/*` and `/api/admin/*`. On non-admin: redirect to `/` (UI) or 403 JSON (API). Match config: `matcher: ['/admin/:path*', '/api/admin/:path*']`. EXCLUDE the existing api-key path (`/api/admin/apps`, `/api/admin/devices`, `/api/admin/icon-upload`) by allow-listing them in middleware to preserve their `x-api-key` flow until T3 migrates them.

**Why a separate `auth-admin.ts`:** keeps existing `lib/auth.ts` surface untouched (zero regression risk for login/register paths). New helper composes `getSession()` + queries `is_admin` column.

**Critical edge:** Middleware runs on Edge Runtime — `pg.Pool` is Node-only. Must NOT import `lib/db` or `lib/auth`. Middleware does ONLY cookie presence + `x-api-key` allowlist + lightweight Supabase REST call (via `getSupabaseService()` IF that lib is Edge-safe — `@supabase/supabase-js` IS Edge-safe). Alternative: middleware just checks cookie EXISTS; route handlers themselves call `requireAdmin()` for the actual `is_admin=true` enforcement. **Choice: route-handler enforcement.** Middleware is a soft-gate (presence check + redirect for `/admin/*` UI routes), real enforcement lives in `requireAdmin()` called inside each route handler. This avoids Edge runtime trauma and matches Next.js idiom.

**`auth-admin.ts` exports:**

```typescript
export interface AdminContext {
  userId: string;
  username: string;
  email: string;
  isAdmin: true;
}

export async function getSessionUserWithAdmin(req: NextRequest): Promise<(SessionUser & { isAdmin: boolean }) | null>;

export async function requireAdmin(req: NextRequest): Promise<AdminContext | NextResponse>;
// Returns NextResponse (401 or 403) on failure; AdminContext on success.
// Touches users.last_seen_at = NOW() as a side effect (best-effort, swallowed errors).
```

**Middleware logic (Edge-safe):**
- If path matches `/api/admin/{apps,devices,icon-upload}/*` → `next()` (legacy x-api-key path preserved).
- If path matches `/api/admin/*` → if no `liv_session` cookie → 401 JSON.
- If path matches `/admin/*` (UI) → if no `liv_session` cookie → redirect to `/login?next=...`.

**Acceptance:**
- `curl /api/admin/metrics/summary` (no cookie) → 401.
- `curl /api/admin/metrics/summary` with non-admin cookie → 403 (enforced by `requireAdmin()` in T3).
- `curl /api/admin/apps` (existing x-api-key path) → still 200 with valid key (legacy preserved).

**Commit:** `feat(212-01): T2 — admin auth helper + middleware (route-handler enforcement)`

### T4 — Bandwidth rollup tables + writer

**File:** `platform/web/src/db/migrations/0014_phase_212_bandwidth_rollups.sql` (also apply via `mcp__supabase__apply_migration` `name=phase_212_bandwidth_rollups`).

**SQL:**

```sql
-- Phase 212: bandwidth_usage rollups for admin dashboard.

CREATE TABLE IF NOT EXISTS public.hourly_bandwidth (
  hour_start  TIMESTAMPTZ NOT NULL,
  user_id     UUID NOT NULL REFERENCES public.users(id) ON DELETE CASCADE,
  bytes_in    BIGINT NOT NULL DEFAULT 0,
  bytes_out   BIGINT NOT NULL DEFAULT 0,
  PRIMARY KEY (hour_start, user_id)
);

CREATE TABLE IF NOT EXISTS public.daily_bandwidth (
  day_start  DATE NOT NULL,
  user_id    UUID NOT NULL REFERENCES public.users(id) ON DELETE CASCADE,
  bytes_in   BIGINT NOT NULL DEFAULT 0,
  bytes_out  BIGINT NOT NULL DEFAULT 0,
  PRIMARY KEY (day_start, user_id)
);

CREATE INDEX IF NOT EXISTS hourly_bandwidth_hour_idx ON public.hourly_bandwidth (hour_start DESC);
CREATE INDEX IF NOT EXISTS daily_bandwidth_day_idx ON public.daily_bandwidth (day_start DESC);

-- Writer: a Postgres function + trigger on bandwidth_usage that upserts into hourly + daily.
-- bandwidth_usage uses period_month (YYYY-MM) granularity, so we synthesize hour/day from updated_at.

CREATE OR REPLACE FUNCTION public.bandwidth_rollup_upsert() RETURNS TRIGGER AS $$
DECLARE
  delta_in BIGINT;
  delta_out BIGINT;
BEGIN
  -- Compute delta (NEW - OLD) to handle UPDATE; for INSERT use NEW only.
  IF TG_OP = 'INSERT' THEN
    delta_in := NEW.bytes_in;
    delta_out := NEW.bytes_out;
  ELSE
    delta_in := NEW.bytes_in - COALESCE(OLD.bytes_in, 0);
    delta_out := NEW.bytes_out - COALESCE(OLD.bytes_out, 0);
  END IF;

  -- Hourly rollup
  INSERT INTO public.hourly_bandwidth (hour_start, user_id, bytes_in, bytes_out)
    VALUES (date_trunc('hour', NEW.updated_at), NEW.user_id, delta_in, delta_out)
    ON CONFLICT (hour_start, user_id)
    DO UPDATE SET
      bytes_in = public.hourly_bandwidth.bytes_in + EXCLUDED.bytes_in,
      bytes_out = public.hourly_bandwidth.bytes_out + EXCLUDED.bytes_out;

  -- Daily rollup
  INSERT INTO public.daily_bandwidth (day_start, user_id, bytes_in, bytes_out)
    VALUES (date_trunc('day', NEW.updated_at)::date, NEW.user_id, delta_in, delta_out)
    ON CONFLICT (day_start, user_id)
    DO UPDATE SET
      bytes_in = public.daily_bandwidth.bytes_in + EXCLUDED.bytes_in,
      bytes_out = public.daily_bandwidth.bytes_out + EXCLUDED.bytes_out;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS bandwidth_rollup_trigger ON public.bandwidth_usage;
CREATE TRIGGER bandwidth_rollup_trigger
  AFTER INSERT OR UPDATE ON public.bandwidth_usage
  FOR EACH ROW EXECUTE FUNCTION public.bandwidth_rollup_upsert();
```

**Acceptance:**
- Tables exist; trigger exists.
- Lag is effectively zero (synchronous trigger; satisfies ADM-12 <5min lag).
- Manual smoke: INSERT a fake row into bandwidth_usage with bytes_in=1000 → hourly_bandwidth row appears with bytes_in=1000.
