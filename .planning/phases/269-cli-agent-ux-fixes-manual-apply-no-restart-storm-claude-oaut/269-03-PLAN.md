<objective>
WS3 — auth-gated agent list. AionUi lists every INSTALLED CLI regardless of auth (operator: "CLI auth'lu değil ise neden gözüküyor main sayfada?") — unauthed agents appear in the picker but fail in chat.

`/liv/api/*` is a **Caddy** reverse-proxy to AionUi :3020 (NOT a livinityd proxy — pitfall P-1). Add a Caddy EXACT-path carve-out `@liv_agents path /liv/api/agents` → :8080 (more specific than `@liv/api/*`, emitted BEFORE it, mirroring LIV_CLI_INSTALLER_HANDLE), plus a new livinityd `GET /api/agents` overlay route that fetches AionUi's real list, joins LivOS auth status via an inverted `BIN_TO_CLI_NAME` map, and filters/badges unauthed agents. The "authed" rule combines the `'failed'` negative signal + AionUi `available`/`enabled` (NOT `=== 'ok'` alone — the 3600s TTL would wrongly re-hide working agents, pitfall P-2). The route fails OPEN — any Redis/AionUi error returns AionUi's list verbatim (pitfall P-3).

⚠ This plan touches Caddy (caddy.ts). Per project memory, Caddy gate changes are easy to break and string-level tests can't catch a fail-open/fail-closed gate — so this plan is `autonomous: false` with an explicit operator LIVE-VERIFY checkpoint (a curl matrix post-deploy).

Purpose: only usable (authed) agents are presented as ready in the picker.
Output: the carve-out + overlay route + the join/filter module, all fail-open, live-verified by the operator.
