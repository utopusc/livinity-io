WS4 — use AionUi's built-in icons. AionUi ships a complete logo set at `/api/assets/logos/{category}/{name}.{svg,png}` (LivOS prefix `/liv` → `/liv/api/assets/logos/...`, routed by Caddy `@aionui_assets` + `@liv_api_subresource`). Point the 267-04 agent-logo map at AionUi's authoritative asset URLs FIRST, with the 267 static SVG / monogram as the final fallback.

Two surfaces, two rules:
1. Agents AionUi enumerates (`/api/agents`) carry their OWN authoritative `agent.icon` — use it directly (WS3's picker surface; no mapping needed).
2. Install-panel CLIs not yet installed have no `agent.icon` — map `CliName → candidate AionUi asset URL` with the onerror cascade (AionUi → 267 `/agent-logos/<logo>.svg` → monogram). Several AionUi assets 404 (qwen/copilot/goose/kimi) so the onerror cascade is LOAD-BEARING — never assume an asset exists.

Purpose: richer, authoritative brand icons with graceful degradation.
Output: a 3-tier src cascade in both the React <AgentLogo> and the panel renderIcon, driven by a small per-CLI candidate list.
</objective>
