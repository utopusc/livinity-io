<objective>
WS2 — claude OAuth paste-back via node-pty. The bare `claude` login spawned via `child_process.spawn` gets a PIPE stdin; claude interprets "non-TTY pipe + no --print" as `--print` mode and errors `no stdin data received in 3s … Input must be provided … when using --print` (confirmed live: `[cli-installer] auth exit 1 for claude-code (4142ms)`). The interactive `Paste code here if prompted` prompt only renders on a real TTY.

Run the claude login under node-pty (already a livinityd dep — `pty-sessions/session.ts` proves the surface). Widen the 268-01 `LiveAuth` registry to a `child | pty` discriminated union; branch the authCli spawn on `branch === 'paste-back'` (claude-code ONLY); run `parseDeviceCode` on `pty.onData`; detect completion via `pty.onExit(exitCode===0)`; make `sendAuthInput` write `pty.write(code + '\r')` for pty backings (vs `child.stdin.write(code + '\n')`). Keep ALL device-poll CLIs on child_process and keep the ANTHROPIC_API_KEY fallback fully intact (it is the guaranteed path given upstream regressions #47994).

Purpose: claude headless code-paste actually works (or falls cleanly back to api-key).
Output: an isolated pty branch inside authCli + the registry union + one sendAuthInput write line — the Redis status contract, device-code stream, timeout, AuthResult shape, and router/UI flow ALL unchanged.
