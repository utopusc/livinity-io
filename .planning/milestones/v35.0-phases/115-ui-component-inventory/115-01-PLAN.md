**Classification rules (apply in order — first match wins):**

1. File is under `shadcn-components/` → tag `replace-with-library`, idiom `shadcn`. Purpose = "shadcn/ui primitive: {name}" (e.g., shadcn/ui primitive: Dialog).
2. File is `init.tsx`, `main.tsx`, `router.tsx`, `types.d.ts` style bootstrap with no JSX rendering UI → tag `wontfix`, idiom `n/a`, note "Bootstrap/config; not a visual component".
3. File's first 40 lines show ONLY Tailwind utility classes and no inline style / no module CSS / no framer-motion → idiom `Tailwind utility`. Tag = `needs-migration` unless:
   - The file imports from `@/shadcn-components/` AND its primary purpose is to wrap a single shadcn primitive → tag `replace-with-library`.
   - The file has very simple structure (single h1/p with no interactive elements) → tag `canonical` only if it manifestly uses no styles that conflict with dashboard.html tokens.
4. File uses `framer-motion` → note "uses framer-motion" in Notes column; tag = `needs-migration` (motion patterns will be restandardized in Phase 116).
5. File uses inline `style={{...}}` heavily (>5 occurrences in first 40 lines) → idiom `bespoke`, tag = `needs-migration`, note the bespoke styling pattern (e.g., "inline gradient styles", "css-in-js color overrides").
6. File imports a `.module.css` file → idiom `bespoke (CSS modules)`, tag `needs-migration`.
7. File's purpose cannot be inferred from first 40 lines AND filename is non-obvious → tag `unknown`, note "agent could not classify; operator review needed".
8. Otherwise (default for typical Tailwind utility-first feature components) → tag `needs-migration`.

**Primary-purpose heuristic (1-line summary):**
- Use the file's default export name + the first JSX element returned + any leading JSDoc.
- Examples:
  - `export default function AppStoreContent()` returning `<div className="app-store ...">` → "App Store window content shell"
  - `export const SettingsAccount = ()` returning `<SettingsPanel>` → "Settings → Account panel"
  - `// Dock for desktop chrome` JSDoc → use that verbatim if present.

**Route/feature heuristic:**
- Under `routes/`: derive from filepath (e.g. `routes/settings/account/page.tsx` → "Settings → Account").
- Under `modules/`: top-level module folder is the feature (e.g. `modules/app-store/X.tsx` → "App Store").
- Under `features/`: top-level feature folder (e.g. `features/backups/X.tsx` → "Backups").
- Under `components/`, `shadcn-components/`, `layouts/`, `providers/`: "shared (cross-feature)".

**Volume guidance (mandatory):**
- Aim for 1 row per file. Do not skip files. Do not collapse rows.
