<objective>
Restyle the AI Chat surface to canonical design tokens. The chat surface is the showcase for v35.0 alignment — `livinity.io/dashboard` has a bento-card aesthetic and the chat should feel like a dashboard card containing a conversation.

Targets (5 files, mapped from CONTEXT.md "chat input, panel, slash-command-menu" — actual paths discovered from `routes/ai-chat/`):
1. `livos/packages/ui/src/routes/ai-chat/index.tsx` — Chat route root (the "panel")
2. `livos/packages/ui/src/routes/ai-chat/chat-input.tsx` — Composer (input + send button + attachments)
3. `livos/packages/ui/src/routes/ai-chat/chat-messages.tsx` — Message list (user + assistant bubbles)
4. `livos/packages/ui/src/routes/ai-chat/slash-command-menu.tsx` — Slash command palette
5. `livos/packages/ui/src/routes/ai-chat/streaming-message.tsx` — Live streaming message component

Note on selection: CONTEXT.md called out 4 files (input, panel, slash-command-menu, welcome-screen). Codebase discovery shows the actual structure is index.tsx (panel) + chat-input + chat-messages + slash-command-menu + streaming-message. There is no separate "welcome-screen" file — that state is conditionally rendered inside `index.tsx` or `chat-messages.tsx`. We migrate the 5 actual files (still within Wave-1 30-component cap, contributing 5 components).

Purpose: AI chat is the most differentiated Mini PC surface vs commodity OwnCloud functionality. Aligning it with canonical dashboard aesthetic strengthens v35.0's "consistent LivOS visual identity" thesis.

Output: 5 chat surfaces restyled, liv-agent stream wiring intact, keyboard shortcuts preserved, operator UAT validates chat round-trip.
</objective>

|---|---|
| Chat root background `bg-white` / `bg-zinc-50` | `bg-card-bg` |

**CRITICAL functional-diff guard for chat:**
- The chat surface integrates with the liv-agent SSE stream (`POST /api/agent/stream`). Every `EventSource`, `fetch`-with-stream, every `onmessage` / `onerror` handler MUST be preserved byte-identical.
- Every `useChatStore` / zustand selector call preserved.
- Every keyboard handler preserved:
  * `onKeyDown` for Enter-to-send (without Shift)
  * `onKeyDown` for `/` to open slash menu
  * `onKeyDown` for ArrowUp/Down to navigate slash menu
  * `onKeyDown` for Escape to dismiss slash menu
- Every markdown renderer (`react-markdown` with `remarkGfm` / `remarkBreaks`) call preserved.
- Every shiki code-highlight call preserved.
- Every streaming-progress indicator (the `streaming-message.tsx` ticker/cursor) preserved structurally — the file may use `<TypewriterCaret>` (a motion primitive); leave that intact.
- Every i18n `t(...)` call preserved.

**DO NOT** replace the chat input `<textarea>` with ui-kit `<Input>`. The chat input is a multi-line textarea with auto-grow, slash-trigger detection, file-attach, and keyboard handling — too entangled to swap. Only restyle the textarea's className (surface + border + focus ring) and the SEND button next to it.

**DO NOT** replace the message-list `<div>` or the virtualized list (if `react-window` is used) — those are infrastructure. Only restyle the bubble surfaces inside the map iteration.
