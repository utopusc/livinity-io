<objective>
Restyle the Settings shell + 5 highest-traffic Settings panels to canonical design tokens + ui-kit primitives. Visual layer only — every tRPC mutation call, every form `onSubmit`, every toggle handler, every navigation binding preserved verbatim.

Targets (6 files, mapped from CONTEXT.md "Settings shell + 5 most-used Settings panels" — actual paths discovered from inventory):
1. `livos/packages/ui/src/routes/settings/index.tsx` — Settings shell (route root, sidebar nav)
2. `livos/packages/ui/src/routes/settings/advanced.tsx` — Advanced panel
3. `livos/packages/ui/src/routes/settings/change-name.tsx` — Change-name form (Account panel)
4. `livos/packages/ui/src/routes/settings/change-password.tsx` — Change-password form (Account panel)
5. `livos/packages/ui/src/routes/settings/troubleshoot/index.tsx` — Troubleshoot panel
6. `livos/packages/ui/src/routes/settings/software-update-confirm.tsx` — Software-update confirm dialog

Rationale for selection: Per CONTEXT.md plan list, "general, account, advanced, troubleshoot, software-update". The Mini PC v7.0 codebase organizes account-related controls as separate routes (`change-name`, `change-password`) rather than a single "account.tsx" file. We migrate the two most-touched account forms (name + password) — equivalent traffic to a single "Account" panel. The "General" panel concept maps to `index.tsx` (the shell with the top-level toggles).

Purpose: Settings is the second-most-trafficked surface after the desktop (every Mini PC operator visits Settings to manage users, software updates, troubleshooting). Restyling these surfaces aligns Mini PC's most-used config UI with `livinity.io/dashboard`.

Output: 6 components restyled, build PASS, behavioral-diff clean, operator UAT validates settings still work end-to-end.
</objective>
