Restyle the App Store window's 4 highest-traffic surfaces to canonical design tokens. App Store is bruce's primary daily interaction surface for installing apps onto the Mini PC (per memory: "auto-synced from livinity-apps repo... 304 manifests"). Visual alignment with `livinity.io/dashboard` makes the experience cohesive across the public store landing and the Mini PC local app store.

1. `livos/packages/ui/src/modules/app-store/app-store-nav.tsx` — Top nav (Discover / Installed / Updates tabs)
2. `livos/packages/ui/src/modules/app-store/app-page/app-content.tsx` — App detail page content shell

Canonical Tailwind utilities (same set as Plans 120-02 / 120-03 / 120-04):
- Colors: `bg-accent-blue`, `bg-accent-green`, `bg-accent-amber`, `bg-accent-red`, `text-accent-*`, `bg-card-bg`, `bg-card-bg-2`, `border-dash-line`, `border-dash-line-strong`

- Spacing: `p-dash`, `gap-dash` (28px)
- Shadow: `shadow-card`
- Motion: `duration-dash` (180ms)

Token-to-existing-class mapping (App Store specific):
| Existing | Replace with |
|---|---|
| Nav tab active `border-blue-600` / `text-blue-600` | `border-accent-blue text-accent-blue` |
| Nav tab inactive hover `text-zinc-700` | leave (text-secondary domain — not in token mapping) |
| App tile background `bg-white` / `bg-zinc-50` | `bg-card-bg-2` |
| App tile hover `hover:shadow-lg` | `hover:shadow-card duration-dash` |
| App tile radius `rounded-2xl` | `rounded-dash` |
| App tile border `border-zinc-200` | `border-dash-line` |
| App detail card sections `bg-white rounded-2xl p-6` | `bg-card-bg rounded-dash p-dash` (or wrap section in `<Card>`) |
| "Verified" badge `bg-green-100 text-green-700` | `<Pill tone="ok">` |
| "Featured" badge `bg-amber-100 text-amber-700` | `<Pill tone="warn">` (warn tone maps to amber per design-tokens) |
| "Beta" / "Not verified" badge `bg-zinc-100 text-zinc-700` | `<Pill tone="neutral">` |
| Install button `bg-blue-600` | `<Button variant="solid">Install</Button>` |
| Uninstall button (destructive) `bg-red-600` or destructive variant | `<Button variant="danger">Uninstall</Button>` |
| "Update available" indicator `text-amber-600` | `text-accent-amber` |

**Functional-diff guard for App Store:**
- Every tRPC mutation (`installApp`, `uninstallApp`, `updateApp`) preserved byte-identical
- Every navigation (`useNavigate`, `<Link to=>`) preserved
- Every per-app slug routing preserved
- Every install-confirmation modal trigger preserved
- Every dependency-resolution dialog trigger preserved (Apps can require other apps)
- Every "open app" handler preserved (clicking an installed app opens its window)
- React keys on the app grid (`key={app.slug}` or `key={app.id}`) preserved

**DO NOT** swap install/uninstall buttons to ui-kit `<Button>` if doing so would lose any data attribute, ref, aria attribute, or test-id used by tests or external e2e. When in doubt: restyle in place rather than swap. The SAFE swap is the `<Pill>` for verified/featured badges (small, stateless, well-isolated).

**DO NOT** modify the dependency-resolution dialog, default-credentials dialog, or app-settings dialog — those are NOT in this plan's scope (separate files in `app-page/` not included in `files_modified`).
